## Introduction

Дерево исследований игры строится в рантайме одной большой областью: 97 технологий семи типов раскиданы по рядам `Technology.Offset` (от −10 до 9) и по годам (x = (Year − 1971) × (50 + ширина кнопки)), между ними — линии зависимостей. Игроки пишут, что дерево перегружено и пугает, а один игрок часами не замечал доступные улучшения. Автор игры сам предлагал подсказку со всеми накопленными модификаторами. Отдельно игроки просят сравнить два процессора бок о бок: инспектор показывает только один CPU.

Фича добавляет поверх существующих окон игры только интерфейс: вкладки по категориям, компактный список, отметки «новое», подробные подсказки (почему исследование идёт так долго и сколько стоит), панель «Все модификаторы» и окно сравнения двух CPU. Баланс игры не меняется: фича читает состояние игры и вызывает те же публичные методы, что и родные кнопки.

Фича также даёт другим модам точки расширения: вкладку в дереве исследований (её использует `cpu-architectures`), строки в окне сравнения, строки в панели модификаторов, строки подсказки технологии и признак «лаборатория занята исследованием другой фичи» (архитектуры используют общую лабораторию с технологиями).

### Feature Summary

UI-пакет дерева исследований: вкладки по категориям, компактный список с фильтрами, метки новых технологий, подробные подсказки технологий и модификаторов, сравнение двух CPU и API расширения для других фич.

### Business Value

- **Для игрока**: меньше визуального шума (вкладка показывает только нужную категорию), ни одна доступная технология не теряется (метки «новое», счётчики, напоминание о простое лаборатории), понятные цифры (штраф за опережение года до +350 % в год, стоимость исследования, вклад каждого модификатора), быстрый выбор между своими и чужими CPU.
- **Доказательства спроса** (IDEAS.md, I22): «tree is cluttered and intimidating», игрок «missed other upgrades for hours», разработчик сам предложил «Additional Modifiers tooltip»; просьбы о сравнении чипов в Inspector. Источники — комментарии itch.io выше.
- **Для проекта**: точка расширения дерева нужна `cpu-architectures` (волна 4), иначе каждая фича патчила бы окно исследований сама.
- **В игре уже есть** (частично): дерево и слайдер финансирования, заготовка `ResearchList` (заголовок «тип (n/m)»), подсказки `TooltipHandler`. Накопленные модификаторы нигде не показаны.

### Scope

**Входит:**
- вкладки категорий над деревом (`ResearchTreeWindow`): «Все» и 7 типов `TechnologyType` (Package, Lithography, Memory, Frequency, CacheSize, WaferSize, Multicore) плюс вкладки других модов через API;
- переключатель «Дерево / Список», компактный список с фильтрами и сортировкой;
- метки «новое» на кнопках дерева и в списке, счётчики на вкладках; «просмотренные» хранятся в сейве;
- подробная подсказка технологии при наведении (в дереве и в списке) через `ModUI.Tooltip` ядра;
- панель «Все модификаторы» (скорость и стоимость исследований, накопленные `ResearchModifiers`, исследовательские проекты в работе, прочие `ModifierType` компании игрока, вклад модов по источникам из `ModModifiers.Explain`);
- окно сравнения двух CPU с дельтами; кнопка «Сравнить» в окне инспектора (`InspectorWindow`) и вход из хаба «Моды»;
- API расширения: вкладки, строки сравнения, строки панели модификаторов, строки подсказки технологии, признак занятой лаборатории;
- напоминания (включены по умолчанию): новые доступные исследования, простой лаборатории;
- настройки фичи в `ModSettings`, запоминание вида в `ModProfile`; выключение без следов;
- регулируемая ширина боковой панели `SideWindow` (Could, FR-10).

**Не входит:**
- любые изменения баланса, формул, времени и стоимости исследований (это зона `mod-framework`/`ModModifiers` и контентных фич);
- новые технологии и ветки исследований (архитектуры — `cpu-architectures`, GPU — `gpu-product-line`);
- компактная перекладка рядов дерева (сжатие пустых рядов) — решение владельца: не делаем, вкладка только скрывает кнопки и линии;
- панель разведки по соперникам (`rival-personalities`), прогнозы рынка (I04), журнал решений автоматики (I27);
- изменения окна `ResearchProjectWindow` (исследовательские проекты) — только чтение для панели модификаторов.

## Requirements

### FR-1: Вкладки категорий в дереве исследований

**User Story:** Как игрок, я хочу переключать вкладки категорий над деревом исследований, чтобы видеть только технологии одного типа и не теряться в общей схеме.

**Priority**: Must

#### Acceptance Criteria

1. WHEN окно дерева исследований построено (после `ResearchTreeWindow.InitializeUI`) THEN мод SHALL показать полосу вкладок: «Все», «Корпуса», «Техпроцесс», «Память», «Частота», «Кэш», «Пластины», «Ядра» и вкладки, зарегистрированные другими фичами через API (FR-7).
2. WHEN игрок выбирает вкладку категории THEN мод SHALL оставить видимыми только кнопки `ResearchButton`, у которых `Technology.Type` входит в категорию, и только линии зависимостей, оба конца которых видимы.
3. WHEN игрок выбирает вкладку «Все» THEN мод SHALL вернуть видимость всем кнопкам и линиям в исходное состояние игры.
4. WHEN игрок выбирает вкладку категории THEN мод SHALL сдвинуть вид дерева так, чтобы первая доступная (не исследованная, не заблокированная) технология этой вкладки оказалась в видимой области; IF доступных нет THEN мод SHALL сдвинуть вид к последней исследованной технологии вкладки.
5. WHILE выбрана вкладка категории мод SHALL сохранять координаты кнопок и линий игры без изменений (раскладка рядов `Offset` и лет не перестраивается; решение владельца: компактной перекладки нет).
6. WHEN игрок выбирает вкладку другой фичи (FR-7) THEN мод SHALL скрыть область дерева и показать содержимое этой вкладки, построенное её провайдером.
7. WHEN окно открывается повторно или после загрузки сейва THEN мод SHALL восстановить последнюю выбранную вкладку из `ModProfile` (секция `research-tree-ux`); IF вкладки больше нет (фича-провайдер выключена) THEN мод SHALL выбрать «Все».

**Сценарии:**
- **AC-1.1** Given открыто дерево, 97 технологий; When игрок нажимает «Память»; Then видны только 9 кнопок памяти (DIP SRAM, DRAM, SDR, DDR…DDR6) и линии между ними; линии от памяти к кэшу скрыты.
- **AC-1.2** Given выбрана «Память»; When игрок нажимает «Все»; Then видны все кнопки и все линии, как в ванильной игре.
- **AC-1.3** Given 1985 год, из памяти доступна только SDR (DRAM исследована, DDR заблокирована); When игрок открывает «Память»; Then вид центрируется на кнопке SDR.
- **AC-1.4** Given последней была вкладка «Кэш»; When игрок загружает другой сейв и открывает дерево; Then активна вкладка «Кэш».

**Complexity**: Medium
**Dependencies**: `mod-framework` (`ModUI`, `ModProfile`, `ModHooks`, `ModL10n`); FR-7 для вкладок других фич
**Assumptions**: окно строится один раз на сцену (`InitializeUI` через 0,2 с после `Start`); линии зависимостей не перестраиваются игрой после построения

### FR-2: Компактный список исследований

**User Story:** Как игрок, я хочу видеть исследования компактным списком с фильтрами и сортировкой, чтобы быстро найти доступные и выбрать следующее без прокрутки огромной схемы.

**Priority**: Must

#### Acceptance Criteria

1. WHEN игрок переключает вид «Дерево / Список» на «Список» THEN мод SHALL заменить область дерева прокручиваемым списком технологий текущей вкладки, сгруппированным по категориям с заголовком «Категория (исследовано/всего)» по `ResearchSector.ResearchCountOfType`.
2. WHERE строка списка показана мод SHALL выводить: название, год, статус (исследовано / доступно / в работе с % / заблокировано), оставшееся время (`ResearchSector.TimeLeftOf`), стоимость в месяц (`Technology.Cost`, формат игры `StringFormatter.FloatToMoney` + «/m»), отметку «не нужна» для типа компании.
3. WHEN игрок включает фильтры «Только доступные», «Скрыть исследованные», «Скрыть ненужные» THEN мод SHALL обновить список без перезагрузки окна; значения по умолчанию: «Только доступные» = вкл, «Скрыть исследованные» = вкл, «Скрыть ненужные» = выкл.
4. WHEN игрок выбирает сортировку (по году, по оставшемуся времени, по стоимости в месяц) THEN мод SHALL упорядочить строки внутри каждой группы; ничьи — по `Technology.ID`.
5. WHEN игрок нажимает «Исследовать» в строке доступной технологии THEN мод SHALL выполнить тот же путь, что и кнопка дерева: при «ненужной» технологии открыть `UnnecessaryTechnologyWarning.Open(Action)`, иначе вызвать `ResearchSector.SetCurrentResearch(Technology)`, `CurrentResearchUI.SetTechnology(Technology)` и `ResearchTreeWindow.ForceUIUpdate()`.
6. IF технология исследована, заблокирована или уже в работе THEN мод SHALL сделать кнопку «Исследовать» неактивной.
7. WHILE список виден мод SHALL обновлять время, прогресс и статусы раз в игровой день (подписка `FeatureContext.OnTick` на `TickPhase.DayPassed`), а не каждый кадр.
8. IF под фильтры не попадает ни одна технология THEN мод SHALL показать строку «Нет исследований по фильтру» вместо пустоты.
9. WHERE зарегистрирован источник занятости лаборатории (FR-7 п. 7) и он сообщает, что лаборатория игрока занята исследованием другой фичи THEN мод SHALL показать над списком строку «Лаборатория занята: …» с текстом источника; кнопки «Исследовать» остаются активными (конфликт разрешает фича-владелец занятости).

**Сценарии:**
- **AC-2.1** Given вкладка «Все», вид «Список», фильтр «Только доступные»; When наступает новый день; Then время в строках уменьшилось, а исследованная сегодня технология исчезла из списка.
- **AC-2.2** Given компания fabless; When игрок нажимает «Исследовать» у «130nm» (тип Lithography, ненужная для fabless); Then открывается штатное предупреждение игры; после подтверждения технология становится текущей и подсвечена в дереве.
- **AC-2.3** Given сортировка «по времени»; When игрок открывает «Кэш»; Then первой идёт технология с минимальным `TimeLeftOf`.
- **AC-2.4** Given `cpu-architectures` исследует x86 в общей лаборатории; When игрок открывает «Список»; Then над списком строка «Лаборатория занята: Архитектура x86 — 43 %».

**Complexity**: Medium
**Dependencies**: FR-1 (вкладка задаёт набор), `ModUI` (прокручиваемый список, `ButtonUI`, `ToggleUI`, `DropdownUI`, `InfoText`)
**Assumptions**: правило «ненужной» технологии копирует приватный `ResearchButton.TechnologyIsUnnecessary` (fabless: Lithography и WaferSize; foundry: всё, кроме Lithography и WaferSize)

### FR-3: Отметки «новое» и счётчики

**User Story:** Как игрок, я хочу видеть, какие технологии стали доступны с моего последнего просмотра, чтобы не пропускать новые улучшения.

**Priority**: Should

#### Acceptance Criteria

1. WHEN технология становится доступной (не исследована и не заблокирована) и её ID нет в множестве «просмотренных» THEN мод SHALL пометить её кнопку в дереве и строку списка меткой «НОВОЕ».
2. WHERE у вкладки есть непросмотренные доступные технологии мод SHALL показывать в заголовке вкладки счётчик, например «Память (2)».
3. WHEN игрок покидает вкладку (переключает на другую или закрывает окно), на которой были видны помеченные технологии, THEN мод SHALL добавить их ID в множество «просмотренных» и снять метки.
4. WHEN игрок удерживает курсор на помеченной технологии не меньше `hoverSeenSeconds` (0,5 с, `ui.json`; подсказка при этом показывается через `ModUI.Tooltip` ядра) THEN мод SHALL считать её просмотренной.
5. WHEN игра сохраняется THEN мод SHALL записать множество «просмотренных» в секцию `research-tree-ux` бокового файла `ModSave` (участник `IModSaveParticipant`; поле версии `_schema` ведёт ядро, фича своего поля версии не хранит); WHEN сейв загружается THEN мод SHALL восстановить множество; IF секции нет (старый сейв) THEN мод SHALL на `ModTicks.GameReady` (причина `Loaded`) считать просмотренными все технологии, доступные на момент загрузки.
6. WHILE идёт перемотка новой игры (`DateController.IsFastFowardSimulating`) мод SHALL не вычислять метки.
7. WHEN начинается новая игра (`ModTicks.GameReady` с причиной `NewGame`) THEN мод SHALL считать просмотренными все технологии, доступные на старте.

**Сценарии:**
- **AC-3.1** Given исследована «SDR», стала доступна «L1 64 KB»; When игрок открывает дерево; Then у «L1 64 KB» метка «НОВОЕ», у вкладки «Кэш» счётчик (1).
- **AC-3.2** Given метка видна на вкладке «Кэш»; When игрок переключается на «Все»; Then метка снята, счётчик пропал; после сохранения и загрузки метка не возвращается.

**Complexity**: Low
**Dependencies**: FR-1, `ModSave`, `ModTicks`
**Assumptions**: «доступна» = `!IsUnlocked && !IsLocked` по `ResearchSector`; «просмотренные» хранятся в сейве (решение владельца)

### FR-4: Подробная подсказка технологии

**User Story:** Как игрок, я хочу при наведении на технологию видеть, почему она исследуется столько времени и сколько стоит, чтобы осознанно выбирать порядок исследований и финансирование.

**Priority**: Must

#### Acceptance Criteria

1. WHEN игрок наводит курсор на кнопку технологии в дереве или на строку списка THEN мод SHALL через `ModUI.Tooltip` (общий мост ядра к `TooltipHandler.StartTrigger`, родная задержка) показать подсказку: название, тип, год; статус; базовое время `Technology.BaseTime` и текущее `Technology.Time`; оставшееся время при текущем финансировании; стоимость в месяц и ориентировочный остаток затрат; зависимости со статусом каждой; технологии, которые она открывает. Свой мост к `TooltipHandler` фича не пишет.
2. IF `Technology.Year` больше текущего года THEN мод SHALL показать строку «штраф за опережение +X %», где X = (`Technology.Time` / `Technology.BaseTime` − 1) × 100, и пояснение «+350 % за каждый год» (из `TechnologyTimeUpdater.penaltyPerYear` = 350).
3. IF `Technology.Year` меньше текущего года и `Technology.Time` < `Technology.BaseTime` THEN мод SHALL показать строку «бонус за отставание −X %» (до −75 %, `TechnologyTimeUpdater.bonusPerYear` = 15 % в год).
4. WHEN технология доступна THEN мод SHALL показать оставшееся время также при финансировании 50 %, 200 % и (если включён режим инноваций) 500 % через `ResearchSector.TimeLeftOf(Technology, float)`.
5. IF `Technology.BaseTime` = 0 THEN мод SHALL показать «мгновенно» вместо времени и не выполнять деление на время.
6. IF технология «не нужна» для типа компании THEN мод SHALL добавить строку с причиной («fabless не производит пластины»).
7. WHERE другие фичи зарегистрировали строки подсказки (FR-7) мод SHALL добавить их в конец подсказки отдельным блоком.

**Сценарии:**
- **AC-4.1** Given 1990 год, технология «DDR6» (Year 2028, BaseTime 240); When игрок наводит курсор; Then видно «240 дн. базовое → ≈32 160 дн. сейчас, штраф за опережение +13 300 %» (38 лет × 350 %).
- **AC-4.2** Given 2005 год, технология «130nm» (Year 2001, BaseTime 110); When игрок наводит курсор; Then видно «110 дн. → ≈61 дн., бонус за отставание −45 %».
- **AC-4.3** Given «DIP 1970» (BaseTime 0); When наведение; Then «мгновенно», без ошибок в логе.

**Complexity**: Medium
**Dependencies**: `ModL10n`, `ModUI.Tooltip` (мост к `TooltipHandler` перенесён в ядро, решение владельца)
**Assumptions**: `Technology.Time` пересчитывается игрой ежедневно (`TechnologyTimeUpdater.UpdateTechnologyTimes`), мод его только читает

### FR-5: Панель «Все модификаторы»

**User Story:** Как игрок, я хочу одним взглядом видеть все накопленные бонусы и штрафы, влияющие на исследования и компанию, чтобы понимать, откуда берутся скорость и стоимость.

**Priority**: Must

#### Acceptance Criteria

1. WHEN игрок наводит курсор на кнопку «Модификаторы» в окне дерева исследований THEN мод SHALL показать подсказку; WHEN игрок нажимает эту кнопку THEN мод SHALL открыть закреплённую панель с тем же содержимым.
2. WHERE панель показана мод SHALL выводить блок «Скорость исследований»: итог `ResearchMath.ResearchSpeed(Funding, company)`, множитель финансирования √Funding, ванильный бонус IDM ×1,05 (`Modifiers.GetModifier`, тип 0) и вклад модов по источникам (п. 7).
3. WHERE панель показана мод SHALL выводить блок «Стоимость исследований»: множитель типа 4 (`ResearchCost`), стоимость текущего исследования в день и в месяц по формуле `ResearchSector.Team.GetTotalCost`.
4. WHERE панель показана мод SHALL выводить блок «Накопленные бонусы проектов» из `Company.ResearchModifiers`: прирост частоты (`FrequencyIncrease`, формат `StringFormatter.FloatToFrequency`), снижение потребления (`ConsumptionReduction`), рост плотности (`DensityIncrease`), с пояснением влияния на CPU.
5. WHERE у игрока есть исследовательские проекты в работе (`TimerScheduler.GetTimedObjectsOfType<Project>()` с `Project.GetResearchProject()` ≠ null) мод SHALL перечислить их полезную нагрузку и оставшееся время.
6. WHERE панель показана мод SHALL выводить блок «Прочие модификаторы компании» для типов 1, 2, 3, 5, 6 (`MaintainanceCost`, `ConstructionCost`, `DevelopmentCost`, `Taxes`, `Interest`) с ванильной причиной (fabless ×0,67 на разработку, foundry ×0,5 на обслуживание и т. п.).
7. WHEN панель или подсказка строится THEN мод SHALL получить разбивку вклада модов по источникам через `ModModifiers.Explain(канал, {Company = игрок})` для каналов `research.speed`, `factory.operatingCost`, `construction.cost`, `development.cost`, `research.cost`, `taxes`, `bank.interest` и показать каждый `AppliedModifier` отдельной строкой: фича-источник, причина (`ReasonKey` и `ReasonArgs`, переведённые ключом L10n фичи-источника), множитель, срок (`ExpiresOn`); IF `IsBalanceCapped` или `IsFuseCapped` THEN мод SHALL дописать к итогу «(ограничено)» (`core.explain.capped`); IF `Explain` недоступен (исключение) THEN мод SHALL показать одной строкой «Моды: ×k», где k = итог / ванильное значение.
8. WHERE другие фичи зарегистрировали источники строк (FR-7) мод SHALL добавить их блоки (например, «Архитектуры» от `cpu-architectures`).

**Сценарии:**
- **AC-5.1** Given IDM-компания, финансирование 150 %, модов-модификаторов нет; When наведение на «Модификаторы»; Then «Скорость ×1,29 = √1,5 (×1,22) × IDM (×1,05) × моды (×1,00)».
- **AC-5.2** Given завершён проект «Частота» за 1B (прирост = 5 % от максимальной частоты на момент покупки, `ResearchMath.Frequency`) и идёт проект «Плотность» за 100M; When открыта панель; Then видны «Макс. частота +N (накоплено)», где N = `ResearchModifiers.FrequencyIncrease`, и «Плотность +1 % — готово через N дн.».
- **AC-5.3** Given компания fabless; When открыта панель; Then «Разработка ×0,67 (fabless)».
- **AC-5.4** Given активна запись `research.speed` ×1,25 фичи `event-system` (причина из её L10n, срок 20 дней); When наведение на «Модификаторы»; Then в блоке «Скорость» отдельная строка «event-system: ×1,25 — <причина> (ещё 20 дн.)», итог пересчитан.

**Complexity**: Medium
**Dependencies**: `mod-framework` (`ModModifiers.Explain`), FR-7
**Assumptions**: ванильная таблица `Modifiers.GetModifier` для игрока воспроизводима чистой функцией (константы 1,05 / 0,5 / 0,8 / 0,67 / 6,0 / 0,25); итог `Modifiers.GetModifier` уже содержит вклад модов (постфикс P1 ядра), поэтому «ваниль» = итог / `Explain.Total`

### FR-6: Сравнение двух CPU

**User Story:** Как игрок, я хочу поставить два процессора (свой и чужой или два своих) рядом, чтобы видеть разницу по каждому параметру и решать, чем отвечать конкурентам.

**Priority**: Must

#### Acceptance Criteria

1. WHEN окно инспектора (`InspectorWindow`) построено THEN мод SHALL добавить рядом с кнопкой «Detailed/Simplified» кнопку «Сравнить» (решение владельца: кнопка только в `InspectorWindow` и в хабе «Моды», не в `HardwareWindow` и не в карточке продаж).
2. WHEN игрок нажимает «Сравнить» THEN мод SHALL открыть окно сравнения, где CPU A = CPU, выбранный в инспекторе, а CPU B выбирается парой выпадающих списков «Компания» и «CPU».
3. WHERE окно сравнения открыто мод SHALL выводить строки: компания, корпус, техпроцесс, ядра, SMT, площадь, транзисторы, температура, потребление, частота, IPC, IPS, память, L1/L2/L3, выход годных, себестоимость, цена, маржа, год, средняя популярность, продано за прошлый месяц, IPS на ватт, IPS на доллар — и колонку разницы в процентах.
4. WHEN разница по метрике с направлением «больше лучше» или «меньше лучше» не меньше порога 2,5 % THEN мод SHALL подсветить лучшую сторону цветом `Colors` игры (положительный/отрицательный).
5. IF значение CPU A равно 0 или метрика не числовая THEN мод SHALL показывать в колонке разницы «—».
6. WHEN игрок нажимает «Поменять местами» THEN мод SHALL переставить A и B.
7. IF выбранный CPU стал недоступен (компания обанкротилась, CPU удалён из списков) THEN мод SHALL сбросить выбор на «—» без исключений.
8. WHERE другие фичи зарегистрировали строки сравнения (FR-7) мод SHALL добавить их (например, «Архитектура»).
9. WHEN окно сравнения открыто из хаба «Моды» THEN мод SHALL предложить A = последний выпущенный CPU игрока.
10. WHERE в B выбран CPU соперника мод SHALL читать те же поля CPU, которые игра показывает в инспекторе и окнах рынка для любой компании, и не раскрывать данных, которых игра не показывает (например, внутренние цели ИИ `CpuBase.AIStrategy`).

**Сценарии:**
- **AC-6.1** Given в инспекторе выбран CPU игрока; When «Сравнить» и выбран CPU Intel; Then 25+ строк, у IPS разница «+18 %» подсвечена на стороне Intel.
- **AC-6.2** Given A и B — один и тот же CPU; When сравнение; Then все разницы 0 %, подсветки нет.
- **AC-6.3** Given в B выбран CPU компании, которая обанкротилась на следующий день; When игрок снова открывает окно; Then B сброшен, ошибок нет.

**Complexity**: Medium
**Dependencies**: `ModUI` (окно, `DropdownUI`, `InfoText`), FR-7
**Assumptions**: форматы значений берутся из `StringFormatter` игры (`FloatToIps`, `FloatToFrequency`, `FloatToMoney`, `CacheString`, `CoreCountString`, `FloatToPercentageString`, `FloatToString`)

### FR-7: Точки расширения для других фич

**User Story:** Как автор другой фичи мода (например, `cpu-architectures`), я хочу добавить свою вкладку в дерево исследований, строки в окно сравнения и в панель модификаторов, не патча окна игры сам, чтобы фичи не конфликтовали.

**Priority**: Must

#### Acceptance Criteria

1. WHEN фича вызывает `ResearchTreeUxApi.RegisterTab(IResearchTabProvider)` в любой момент (до или после построения окна) THEN мод SHALL добавить вкладку при ближайшем построении полосы вкладок в порядке `Order`.
2. WHEN вкладка провайдера впервые выбрана THEN мод SHALL один раз вызвать `BuildContent(RectTransform)` и затем вызывать `OnShown()`/`OnHidden()` при переключениях.
3. IF провайдер бросает исключение в любом методе THEN мод SHALL сообщить о нём через `ModHooks.ReportFault` фиче-владельцу провайдера (её определяет `ModFeatures.FeatureOfType` по пространству имён типа провайдера; счётчик и circuit breaker ведёт ядро), отключить только эту вкладку (или этот источник строк) до перезапуска и продолжить работу.
4. WHEN фича вызывает `RegisterCompareRows`, `RegisterModifierLines` или `RegisterTechTooltipLines` THEN мод SHALL опрашивать её при каждом построении соответствующего UI.
5. WHEN фича-провайдер выключена (`IResearchTabProvider.IsAvailable()` = false, `ModFeatures.IsActive` = false) THEN мод SHALL скрыть её вкладку и не опрашивать её строки; на `ModFeatures.StateChanged` мод SHALL перестроить полосу вкладок.
6. IF research-tree-ux выключена THEN `ResearchTreeUxApi.IsActive` SHALL возвращать false, а регистрация SHALL проходить без ошибок и без видимого эффекта: регистрации запоминаются и начинают действовать, когда фича снова включена (фичи-клиенты сами выбирают запасной вход).
7. WHEN фича вызывает `RegisterLabOccupancy(ILabOccupancySource)` THEN мод SHALL опрашивать `IsLabBusy()` и `BusyText()` при построении списка (FR-2 п. 9) и в обработчике напоминания о простое (FR-9 п. 2): лаборатория, занятая исследованием фичи-источника, не считается простаивающей.

**Сценарии:**
- **AC-7.1** Given `cpu-architectures` зарегистрировала вкладку «Архитектуры» с `Order` = 200; When игрок открывает дерево; Then вкладка стоит после «Ядра» и показывает панель архитектур.
- **AC-7.2** Given провайдер строки сравнения бросает исключение; When открыто сравнение; Then остальные строки показаны, в `Player.log` одна запись `[PTMod]` с именем провайдера, счётчик ошибок увеличен у фичи-владельца провайдера.
- **AC-7.3** Given фича `cpu-architectures` выключена в хабе; When игрок открывает дерево; Then вкладки «Архитектуры» нет; после включения она появляется без перезагрузки сцены.

**Complexity**: Low
**Dependencies**: FR-1, FR-4, FR-5, FR-6
**Assumptions**: провайдеры живут в той же сборке `PTMod.dll`

### FR-8: Настройки, запоминание вида и выключение

**User Story:** Как игрок, я хочу включать и выключать фичу и чтобы мой выбор вида запоминался, чтобы пользоваться ей как удобно или вернуть ванильное окно.

**Priority**: Must

#### Acceptance Criteria

1. WHERE открыт хаб «Моды» мод SHALL показать переключатель фичи `research-tree-ux` (строит ядро по `IModFeature`), страницу настроек с переключателями напоминаний (`ParamSpec`, FR-9) и кнопку «Сравнить CPU» (`FeatureContext.HubPage`).
2. WHEN игрок меняет вкладку, вид или фильтры списка THEN мод SHALL сохранить выбор в `ModProfile` (секция `research-tree-ux`, `MarkDirty`; глобально, не в сейв).
3. WHEN игрок выключает фичу посреди игры (`SupportsHotToggle` = true) THEN мод SHALL убрать полосу вкладок, список, метки, кнопку «Модификаторы», кнопку «Сравнить» и закрыть окно сравнения, вернуть видимость всем кнопкам и линиям дерева; WHEN игрок включает фичу снова THEN мод SHALL восстановить UI без перезагрузки сцены.
4. WHILE фича выключена мод SHALL не выполнять дневных вычислений этой фичи (обработчики `FeatureContext.OnTick` не вызываются, постфиксы выходят первой строкой).
5. IF мод удалён полностью THEN сейв игры SHALL грузиться в ванильной игре (фича не пишет в файлы сейва игры), а секция `research-tree-ux` бокового файла SHALL игнорироваться.

**Сценарии:**
- **AC-8.1** Given выбрана вкладка «Кэш»; When фича выключается в хабе; Then дерево выглядит как в ванильной игре (все кнопки и линии на месте).

**Complexity**: Low
**Dependencies**: `ModSettings`, `ModProfile`, `ModUI` (хаб «Моды»)
**Assumptions**: нет

### FR-9: Напоминания о доступных исследованиях и простое лаборатории

**User Story:** Как игрок, я хочу получать ненавязчивое уведомление, когда появились новые исследования или лаборатория простаивает, чтобы не терять дни исследований.

**Priority**: Should (владелец включил напоминания в объём и по умолчанию)

#### Acceptance Criteria

1. WHEN в начале месяца (`TickPhase.MonthPassed`) есть непросмотренные доступные технологии (FR-3) и окно дерева закрыто THEN мод SHALL показать `ModNotify` «Доступны новые исследования: N» не чаще одного раза в месяц.
2. WHEN у игрока нет текущего исследования (`ResearchSector.CurrentResearch()` = null) и лаборатория не занята источником из FR-7 п. 7 подряд 7 игровых дней (значение из контента) и есть хотя бы одна доступная технология THEN мод SHALL показать `ModNotify` «Лаборатория простаивает N дн.» и не повторять его раньше чем через 30 дней.
3. WHILE идёт перемотка новой игры или загрузка мод SHALL не генерировать напоминаний (фича нейтральна); показ уведомлений в пакетном прогоне `DateController.NextMonth` откладывает ядро (`ModNotify`, `ModTicks.IsBatchRun`).
4. WHEN игрок выключил напоминание в хабе (`ParamSpec` `notifyNewTech` / `notifyIdleLab`) THEN мод SHALL не показывать этот тип уведомлений.

**Сценарии:**
- **AC-9.1** Given исследование завершилось 1 марта, новое не выбрано; When наступает 8 марта; Then одно уведомление о простое; 9–31 марта повторов нет.
- **AC-9.2** Given `cpu-architectures` исследует архитектуру в общей лаборатории игрока (`ResearchSector.CurrentResearch()` = null); When проходит 7 дней; Then уведомления о простое нет.

**Complexity**: Low
**Dependencies**: FR-3, FR-7 п. 7, `ModNotify`, `ModTicks`
**Assumptions**: напоминания — чистый UI, на баланс не влияют; пороги 7 и 30 дней приняты владельцем

### FR-10: Регулируемая ширина боковой панели (Could)

**User Story:** Как игрок, я хочу менять ширину боковой панели со списком проектов и CPU, чтобы длинные названия помещались.

**Priority**: Could (владелец: «ширина боковой панели — Could», не входит в MVP)

#### Acceptance Criteria

1. WHEN игрок тянет левый край открытой боковой панели `SideWindow` THEN мод SHALL менять её ширину в пределах [1,0; 1,6] × исходной ширины (`ui.json`, `sidebar`) и пересчитывать позицию скрытого состояния так, чтобы закрытая панель полностью уходила за экран.
2. WHEN ширина изменена THEN мод SHALL запомнить множитель в `ModProfile` и применять его при следующем построении сцены.
3. WHEN фича выключается THEN мод SHALL вернуть исходные ширину и позиции `SideWindow`.
4. IF не найдены приватные поля `SideWindow.rectTransform`, `SideWindow.visiblePosition`, `SideWindow.hiddenPosition` THEN мод SHALL отключить только эту часть (`UxParts.Sidebar`), остальное работает.

**Сценарии:**
- **AC-10.1** Given открыта боковая панель; When игрок тянет край влево на 120 px; Then ширина растёт до предела 1,6 × исходной; после перезагрузки сцены ширина та же; при закрытии панель полностью за экраном.

**Complexity**: Low
**Dependencies**: FR-8 (`ModProfile`)
**Assumptions**: под «resizable sidebar» из идеи I22 принята панель `SideWindow` (проекты и CPU) как единственная боковая панель на рабочем столе; формулы ширины проверяются спайком в TSK-021

## Non-Functional Requirements

### NFR-1: Производительность

- WHILE окно дерева закрыто мод SHALL тратить на дневной тик не больше 0,1 мс (проверка «доступно/просмотрено» по 97 технологиям).
- WHEN игрок переключает вкладку THEN мод SHALL применить фильтр (до 97 кнопок и всех линий) не дольше 5 мс.
- WHEN список виден и наступил новый день THEN мод SHALL обновить строки не дольше 3 мс.
- WHEN строится подсказка технологии или панель модификаторов THEN мод SHALL уложиться в 1 мс.
- WHILE идёт перемотка новой игры мод SHALL выходить из постфиксов `ResearchTreeWindow.UpdateButtonStates` до любых вычислений.

### NFR-2: Надёжность

- WHEN в обработчике мода или в постфиксе возникает исключение THEN мод SHALL перехватить его на границе хука через `ModHooks.Guard` (счётчик ошибок, `ModLog` и circuit breaker `hooks.faultThreshold` ведёт ядро; своих счётчиков фича не держит) и не пропустить его в код игры.
- IF самопроверка на старте не нашла цель патча или приватное поле (`researchButtons`, `dependencyLines`, `cpuTab`, `linesParent`, `currentResearchUI`, `simpleOrDetailedButton`, `currentCpu`; для FR-10 — `SideWindow.rectTransform`, `visiblePosition`, `hiddenPosition`) THEN мод SHALL отключить зависящую часть фичи (вкладки, список, сравнение, боковая панель — независимо) и оставить остальные.
- IF линию зависимости не удалось сопоставить паре технологий THEN мод SHALL оставлять её видимой во всех вкладках и записать одно предупреждение в лог.

### NFR-3: Неизменность баланса

- WHILE фича включена мод SHALL не изменять ни одно числовое поле игровой логики и баланса и не патчить формулы; единственные действия с состоянием игры — те же публичные вызовы, что делает родная кнопка дерева (`ResearchSector.SetCurrentResearch`, `CurrentResearchUI.SetTechnology`, `ResearchTreeWindow.ForceUIUpdate`, `UnnecessaryTechnologyWarning.Open`). Исключение — геометрия `SideWindow` в FR-10 (только интерфейс).
- Вклад фичи в `market.rating.cpu` и `popularity.gain` равен нулю (общий предел ядра [0,5; 2,0] фичу не затрагивает).

### NFR-4: Совместимость сейвов

- WHEN загружается сейв без секции `research-tree-ux` THEN мод SHALL использовать значения по умолчанию (FR-3.5).
- WHEN секция записана версией мода новее (ядро: `_schema` больше `SchemaVersion` участника) THEN ядро SHALL выдать участнику значения по умолчанию (`ResetToDefaults`) и записать исходную секцию как есть; WHEN в секции битые данные THEN мод SHALL записать предупреждение, отбросить неверные значения и не потерять секцию при следующем сохранении, если фича выключена.
- Фича SHALL не добавлять поля в классы игры, не писать в файл сейва игры и не хранить собственное поле версии секции (версию `_schema` пишет и читает ядро).

### NFR-5: Локализация

- WHERE мод показывает текст мод SHALL брать его из `ModL10n` (`ru` по умолчанию, `en` фолбэк); названия технологий и компаний — из игры (`Technology.Name`, `ICompany.Name`) как есть, чтобы работал русификатор.
- Ключи фичи SHALL начинаться с `rtux.` (соглашение ядра о префиксах; предикатов, событий и писем фича не вводит). Каждый ключ SHALL существовать в обоих файлах `ru.json` и `en.json` (проверяется тестом).

### NFR-6: Удобство

- WHEN тема игры меняется (`ThemeManager.OnThemeChanged`) THEN UI фичи SHALL перекраситься без переоткрытия окна.
- WHERE мод показывает числа мод SHALL использовать форматтеры игры (`StringFormatter`), чтобы формат совпадал с родным UI.
- Полоса вкладок SHALL помещаться в ширину окна дерева; IF вкладок больше, чем помещается, THEN мод SHALL сделать полосу прокручиваемой по горизонтали.

### NFR-7: Совместимость с другими фичами

- Фича SHALL быть единственной, кто патчит `ResearchTreeWindow.InitializeUI` и `InspectorWindow.Start`; другие фичи расширяют UI через FR-7.

### NFR-8: Соответствие контракту ядра

- Фича SHALL быть найдена ядром по `[ModFeature]` как `sealed class … : IModFeature` в пространстве имён `PTMod.Features.ResearchTreeUx` (Id = `research-tree-ux`, `NameKey`, `DescriptionKey`, `DependsOn` — только жёсткие зависимости, `EnabledByDefault`, `SupportsHotToggle`, `Register(FeatureContext)`, `OnEnabled`/`OnDisabled`).
- Фича SHALL получать тики через `FeatureContext.OnTick`, старт игры через `ModTicks.GameReady`, состояние через `IModSaveParticipant`, глобальные данные через `ModProfile`, подсказки через `ModUI.Tooltip`, разбивку модификаторов через `ModModifiers.Explain`; прямые подписки на `DateController`, `Player.OnNewGame`, `SaveHandler.*` и собственные счётчики ошибок SHALL отсутствовать.

## Edge cases

- Окно дерева ещё не построено (игрок не дождался 0,2 с после загрузки сцены) — API копит регистрации и применяет их при построении.
- Загрузка сейва перезагружает сцену — индекс кнопок и UI строятся заново в постфиксе `InitializeUI` новой сцены; старые ссылки отбрасываются (ядро сообщает `SceneLeaving`).
- Смена типа компании (`CompanyTypeUpdater.OnCompanyTypeChanged`) — пересчитать «ненужные» в списке и подсказках.
- `Technology.BaseTime` = 0 (DIP 1970, L1 8 KB) — «мгновенно», без деления на 0.
- `ResearchSector.Funding` близко к 0 — время «∞» вместо деления на 0.
- `ResearchDataProvider.GetTechnology` пропускает `id == Count` (ошибка игры) — мод не обращается по ID за пределами `Count − 1`.
- Технология текущего исследования заблокирована (возможно в игре) — статус «в работе (заблокирована)», кнопка «Исследовать» неактивна.
- Все технологии вкладки исследованы — пустое состояние «Всё исследовано».
- CPU сравнения без цены (`Price` = 0) — «IPS на доллар» = «—».
- Две фичи регистрируют вкладку с одинаковым `TabId` — вторая отклоняется с предупреждением.
- Фича выключена в середине игры при открытом окне сравнения — окно закрывается.
- Отрицательное время из-за ошибок данных — показывается «—».
- Лаборатория игрока занята архитектурой (`ResearchSector.CurrentResearch()` = null, но лаборатория не простаивает) — напоминание о простое не показывается, в списке строка «Лаборатория занята: …».
- Источник занятости лаборатории выключен или бросил исключение — лаборатория считается свободной, источник отключается до перезапуска.

## Constraints and Assumptions

### Technical Constraints

- Unity 6000.0.65f1, Mono; UI — только runtime-построение через `ModUI` из шаблонов игры (решение 0005); правка `data.unity3d` запрещена.
- Патчи — Harmony 2.3.6 (решение 0002, accepted) через `ModHooks`; приватные поля читаются через `AccessTools`.
- Подсказки — через `ModUI.Tooltip` ядра (`TooltipHandler.Instance` существует только в сцене), поэтому UI фичи строится в той же сцене.
- Чистая логика фичи (`Features/ResearchTreeUx/Logic/**`) компилируется мини-раннером тестов (.NET Framework 4.8) без Unity и без типов `Assembly-CSharp`: типы технологий и модификаторов передаются целыми значениями (`TechnologyType`, `ModifierType`), код — общее подмножество C# и API .NET Framework 4.8.
- Ссылки на классы игры проверяются скриптом `tools/check_spec_refs.py` по `pt-modding/code/`, ссылки на `Mod*` — режимом `--core-api`.

### Business Constraints

- Проверку в игре выполняет владелец вручную, не во время онлайн-игр с античитом.
- Никаких сетевых обращений.

### Assumptions

- `mod-framework` предоставляет `ModUI` с фабриками кнопок, выпадающих списков, переключателей, полос прогресса, текстов и прокручиваемых списков, подтверждение `ModUI.Confirm`, мост подсказок `ModUI.Tooltip`, а также хаб «Моды».
- `ModModifiers.Explain` отдаёт разбивку множителей по источникам (ядро v0.2).
- Поля `ResearchTreeWindow`, `InspectorWindow`, `CpuUI`, `SideWindow` имеют имена, как в `pt-modding/code/` (проверяется самопроверкой).

## Открытые вопросы владельцу

Остался один вопрос, который `owner-decisions.md` не решает. Он не блокирует реализацию: действует решение по умолчанию.

1. **Сравнение чужих CPU и «туманность» разведки.** Сравнение читает поля CPU соперников так же, как инспектор игры (FR-6 п. 10). Если владелец включит «туманность» сведений в `rival-personalities` (Should), нужно решить, скрывает ли она и поля сравнения. По умолчанию: сравнение показывает ровно то, что показывает инспектор, поэтому правила согласуются автоматически, если `rival-personalities` меняет сам инспектор.

## Glossary

| Термин | Значение |
|---|---|
| Дерево исследований | окно `ResearchTreeWindow` с кнопками `ResearchButton` и линиями зависимостей |
| Вкладка категории | фильтр дерева по `TechnologyType` |
| Доступная технология | не исследована (`IsUnlocked` = false) и не заблокирована (`IsLocked` = false) |
| Ненужная технология | технология, которая не нужна компании её типа (fabless: техпроцесс и пластины; foundry: всё, кроме техпроцесса и пластин) |
| Штраф за опережение | рост `Technology.Time` для технологий будущих лет: +350 % за год (`TechnologyTimeUpdater`) |
| Бонус за отставание | уменьшение `Technology.Time` для технологий прошлых лет: до −75 %, 15 % в год |
| M0 / M4 | модификаторы `Modifiers.GetModifier` типа 0 (скорость) и 4 (стоимость исследований) |
| `ResearchModifiers` | накопленные бонусы исследовательских проектов компании: частота, потребление, плотность |
| Провайдер | объект другой фичи, зарегистрированный в `ResearchTreeUxApi` |
| Просмотренные | множество ID технологий, метки «новое» которых игрок уже видел (хранится в сейве) |
| `Explain` | `ModModifiers.Explain(канал, контекст)`: разбивка итогового множителя по источникам |
| Занятая лаборатория | состояние, когда единственный слот `ResearchSector` занят исследованием другой фичи (архитектура), хотя `CurrentResearch()` = null |
| `_schema` | поле версии секции сейва; пишет и читает ядро, фича его не хранит |
