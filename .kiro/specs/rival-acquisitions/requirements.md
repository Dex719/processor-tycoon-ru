## Introduction

В игре 13 исторических соперников (`AICompany`, индекс `UniqueID` в `CompanySpawner`). Названия компаний в этой спеке — реальные, как в русификаторе (решение владельца): Intel (в коде игры `Inlet`), AMD (`EMD`), Texas Instruments (`Texas`), GlobalFoundries (`SolarFoundries`), TSMC (`TCMS`), Cyrix (`Cyrux`). Идентификаторы кода (`CompanyHelper.IsEMD`, `CompanyEventHandler.TriggerSolarFoundriesSpinOff`) остаются как в игре; отображаемое имя компании мод берёт из игры, а в контенте компании указываются по `UniqueID`.

Соперники разоряются по тому же правилу, что и игрок: 120 дней дефолта (`BankruptcyHandler.TickBankruptcies`), последняя попытка спастись (`AICompany.BankruptcyWarning`: продажа линий, уход в fabless, у AMD — выделение GlobalFoundries) и банкротство (`AICompany.TriggerBankruptcy`: проекты отменены, все CPU сняты, `IsBankrupt = true`). Банкрот остаётся «мёртвым» объектом с заводом и технологиями, которыми никто не пользуется. Игрок не может ни купить соперника, ни спасти его. Разработчик подтвердил, что покупка компаний запланирована, но не сделана.

Мод добавляет рынок слияний для игрока: оценку стоимости каждой компании, покупку активов банкрота, покупку компании в дефолте, враждебное поглощение здоровой компании и покупку доли (спасение) с дивидендами. Ключевая техническая трудность — **как убрать поглощённую компанию, ничего не сломав**: `CompanyHelper` опознаёт сценарные компании по жёстко заданным `UniqueID` (Intel 0, AMD 1, Texas Instruments 3, GlobalFoundries 8, TSMC 9, Cyrix 10), CPU и контракты ссылаются на компании по `SaveID`, а сейв собирает CPU по имени владельца (`DataFinder.FindOwnerOfCompany`). Мод не удаляет и не переименовывает объект `AICompany`, а выводит его штатным путём банкротства.

### Feature Summary

Игрок может купить активы банкрота, купить компанию в дефолте, поглотить здоровую компанию или купить долю соперника; линии, технологии, CPU и контракты переходят к игроку, а поглощённая компания выводится штатным банкротством без поломки ссылок.

### Business Value

- **Ценность для игрока.** Новая стратегическая ось середины и конца игры: деньги можно вложить не только в заводы и исследования, но и в рост через покупки. Банкротство соперника становится возможностью, а не просто тостом в углу экрана. Спасение соперника (доля) даёт дивиденды и позволяет поддержать нужного конкурента.
- **Доказательства спроса.** I06: спрос **medium**, fun **4/5**, трудоёмкость L. Три игрока просили покупку компаний; разработчик подтвердил план, но не реализовал (источники выше). Владелец выбрал I06 в группе «самое интересное по fun».
- **Ценность для проекта.** Даёт другим фичам события сделок (реакции соперников, достижения, исторические антимонопольные дела) и канал `acquisition.price` для влияния на цены.

### Scope

**Входит (in scope):**

- оценка стоимости компании ИИ «для игрока» (деньги, завод, технологии, CPU, доля рынка);
- окно «Сделки»: список соперников, статус, оценка, доступные сделки;
- сделки: покупка активов банкрота (аукцион), покупка компании в дефолте, враждебное поглощение здоровой компании, покупка доли (спасение) с дивидендами, поручение на спасение в последний момент;
- перенос к игроку: линий (или их продажа), технологий, опыта техпроцессов, активных CPU с OEM-контрактами, контрактов цели (как поставщика и как клиента литейщика), флага литейных услуг;
- передача состояния смежных фич (архитектуры, GPU-линейка), если они включены;
- выведение поглощённой компании через `AICompany.TriggerBankruptcy` без удаления объекта и смены ID;
- хуки банкротства ИИ: уведомления о дефолте и банкротстве, снимок CPU перед банкротством;
- предупреждения о последствиях для сценарных компаний (x86-лицензия, GlobalFoundries, литейные услуги Intel);
- события и API для других спек (C#-события `RivalAcquisitionsApi`; канал `acquisition.price`, объявленный реестром ядра);
- настройки, контент-JSON, журнал сделок, `ModSave`.

**Не входит (out of scope):**

- банкротство и спасение **игрока** — спека `bankruptcy-recovery`;
- покупки между компаниями ИИ (ИИ-слияния);
- сохранение бренда после полного поглощения (дочерняя компания под старым именем с остановленным ИИ) — не делается (решение владельца); бренд сохраняется только при покупке доли (компания продолжает работать сама);
- продажа доли обратно (выход из инвестиции) — не делается (решение владельца);
- передача игроку x86-лицензии при покупке Intel или AMD — не делается (решение владельца);
- перенос сотрудников (`Teams` у ИИ в сейвах пусты, IDEAS.md);
- перенос незавершённых проектов цели (CPU в разработке, расширения): они отменяются ванильным `AICompany.TriggerBankruptcy`;
- характеры соперников, их отношение к игроку и реакции на сделки — спека `rival-personalities` (здесь только события);
- антимонопольные ограничения — спека `historical-events` (здесь ограничений нет);
- публикация сделок через `EventBus` `event-system` — не делается (другие фичи подписываются на C#-события API);
- игровой эффект репутации — спека `press-reviews`.

## Requirements

### FR-1: Оценка стоимости компании

**User Story:** Как игрок, я хочу видеть, во сколько оценивается соперник и из чего складывается цена, чтобы понимать, выгодна ли сделка.

**Priority:** Must

#### Acceptance Criteria

1. WHEN игрок открывает окно «Сделки» или превью сделки THEN мод SHALL рассчитать оценку операционных активов `E = (k_fab × ManufacturingDivisionValue + A_tech + A_cpu) × (1 + k_share × s)` по формулам `design.md` и показать каждую составляющую отдельно.
2. WHEN считается `A_tech` THEN мод SHALL учитывать только технологии, исследованные целью и не исследованные игроком, по стоимости `Technology.Cost × Technology.Time / 30`.
3. WHEN считается `A_cpu` THEN мод SHALL суммировать выручку активных CPU цели за последние 12 месяцев (`CpuBase.MarketData.Income`), умноженную на маржу `clamp((Price − RealUnitCost) / Price, 0, 1)`.
4. WHEN считается доля рынка `s` THEN мод SHALL брать `max(MarketDataProvider.MarketShare(цель), MarketDataProvider.FoundryMarketShare(цель))`.
5. IF оценка меньше нижней границы `E_min = 0,25 × D_цели` (`D_цели = ModCredit.DebtLimitOf(цель)`) THEN мод SHALL использовать `E_min`.
6. WHEN для цели зарегистрированы множители канала `acquisition.price` THEN мод SHALL умножить цену сделки на значение канала (`ModModifiers.Get(ModChannels.AcquisitionPrice, {Company = цель})`, балансовые границы [0,5; 3,0] ставит реестр ядра).

#### Scenarios

- **AC-1.1** Given 1985, `D ≈ 111 млн`, у цели 40 линий на 100 мм (`ManufacturingDivisionValue ≈ 147,2 млн`), технологий в разрыве на 24 млн, 2 CPU с выручкой 10 млн/мес и маржой 40 %, доля 8 %; When игрок открывает превью; Then `A_fab ≈ 294,4 млн`, `A_tech = 12 млн`, `A_cpu = 96 млн`, `E ≈ 434,6 млн`.
- **AC-1.2** Given у цели 0 линий, 0 CPU и нет технологий в разрыве; When открыто превью; Then оценка = `E_min = 0,25 × D`.

#### Additional Details

- **Complexity**: Medium
- **Dependencies**: `mod-framework` (`ModModifiers`, `ModCredit`, `ModContent`).
- **Assumptions**: оценка зависит от игрока (разрыв технологий) — это цена для единственного покупателя.

### FR-2: Окно «Сделки»

**User Story:** Как игрок, я хочу видеть всех соперников с их состоянием и доступными сделками в одном окне, чтобы выбирать цель.

**Priority:** Must

#### Acceptance Criteria

1. WHEN игрок открывает страницу фичи в хабе «Моды» (раздел «Сделки») или нажимает действие «Сделки» в письме THEN мод SHALL открыть модальное окно со списком появившихся компаний ИИ (`DataFinder.FindAllAICompanies`).
2. WHILE окно открыто мод SHALL показывать по каждой компании: название и цвет, статус («Здорова», «Дефолт: N дн.», «Банкрот: аукцион до ДАТА», «Поглощена игроком», «Банкрот»), деньги, линии, активные CPU, долю рынка, оценку `E`, долю игрока.
3. WHEN строка выбрана THEN мод SHALL показать доступные сделки с ценой и причины недоступности остальных (подсказка `ModUI.Tooltip`).
4. IF игрок в дефолте или банкрот THEN мод SHALL показать все сделки неактивными с причиной «Компания в дефолте».

#### Scenarios

- **AC-2.1** Given 1990, 9 компаний появилось, одна в дефолте 40 дней; When окно открыто; Then 9 строк, у одной статус «Дефолт: 40 дн.», у неё доступна «Купить компанию (дефолт)» и «Купить долю».
- **AC-2.2** Given игрок в дефолте; When окно открыто; Then все кнопки сделок неактивны с причиной.

#### Additional Details

- **Complexity**: Medium
- **Dependencies**: FR-1, FR-3…FR-6; `mod-framework` (`ModUI`, `FeatureContext.HubPage`).
- **Assumptions**: компании, которые ещё не появились по `spawnDate`, не показываются.

### FR-3: Покупка активов банкрота (аукцион)

**User Story:** Как игрок, я хочу дёшево купить завод, технологии и продукты разорившегося соперника, чтобы его наследие не пропадало.

**Priority:** Must

#### Acceptance Criteria

1. WHEN компания ИИ становится банкротом во время игры (`BankruptcyHandler.OnCompanyWentBankrupt`, не перемотка и не загрузка) THEN мод SHALL открыть по ней аукцион, последний день которого (включительно) — `дата банкротства + auctionDays` календарных дней (`AddDays`, 365 по умолчанию), и отправить письмо с действием «Сделки». Срок считается в днях, не в годах: если в этом промежутке есть 29 февраля, последний день на сутки раньше той же даты следующего года (банкротство 03.05.1987 → последний день 02.05.1988).
2. WHILE аукцион открыт мод SHALL предлагать покупку активов по цене `P = max(E_min, 0,4 × E) × acquisition.price`; денежный остаток и долги банкрота к игроку не переходят.
3. WHEN игрок покупает активы банкрота THEN мод SHALL перенести линии, технологии и опыт техпроцессов (FR-7), а CPU, бывшие активными в момент банкротства (снимок FR-11), вернуть в производство под брендом игрока (FR-8).
4. WHEN срок аукциона истёк или активы куплены THEN мод SHALL закрыть аукцион.
5. IF сейв загружен впервые с модом и в нём есть банкроты без аукциона THEN мод SHALL при `GameReady` (причина `Loaded`) открыть им аукционы на `auctionDays` от даты загрузки без возврата CPU (снимка нет).

#### Scenarios

- **AC-3.1** Given соперник обанкротился 1987-05-03; When игрок открывает «Сделки»; Then статус «Банкрот: аукцион до 02.05.1988» (1987-05-03 + 365 календарных дней; 1988 год високосный, поэтому не 03.05.1988), доступна «Купить активы» — в том числе 1988-05-02, в последний день аукциона.
- **AC-3.2** Given аукцион, `E = 354,4 млн` (CPU из снимка учтены с коэффициентом 0,5, доля рынка 0), `D = 111 млн`; When игрок подтверждает покупку; Then баланс −141,8 млн, линии и технологии перешли, CPU из снимка появились в окне производства, аукцион закрыт.
- **AC-3.3** Given банкротство 1987-05-03 и дата 1988-05-03 (день после последнего дня аукциона; так же и в любой более поздний день); When открыто окно; Then у банкрота статус «Банкрот», сделок нет.

#### Additional Details

- **Complexity**: High
- **Dependencies**: FR-1, FR-7, FR-8, FR-11.
- **Assumptions**: банкрот после `AICompany.TriggerBankruptcy` сохраняет завод и технологии (ванильное поведение).

### FR-4: Покупка компании в дефолте

**User Story:** Как игрок, я хочу купить соперника в дефолте со скидкой вместе с его долгами, пока он не разорился окончательно.

**Priority:** Must

#### Acceptance Criteria

1. WHILE компания ИИ в дефолте (`IsInDefault`) и не банкрот мод SHALL предлагать покупку по цене `P = max(P_f, C⁺ + E_min)`, где `P_f = max(E_min, 0,7 × (E + C⁺)) × acquisition.price × (1 − σ_игрока)`, `C⁺ = max(0, C)`, `C` — денежный остаток цели.
2. WHEN игрок покупает компанию в дефолте THEN мод SHALL принять денежный остаток цели `C` (обычно отрицательный — долг) на баланс игрока и показать в превью итог `NetCash = −P + C`; для этой сделки `NetCash` SHALL быть строго отрицательным при любых `E`, `C`, `σ_игрока` и значении канала `acquisition.price`.
3. WHEN сделка выполнена THEN мод SHALL перенести активы по FR-7…FR-9, вывести цель по FR-10 и передать состояние смежных фич по FR-16.
4. IF баланс игрока после сделки (`money + NetCash`) меньше `minCashAfter` (0) THEN мод SHALL показать сделку неактивной с недостающей суммой (покупки с уходом баланса в минус запрещены).

#### Scenarios

- **AC-4.1** Given цель в дефолте, `E = 434,6 млн`, `C = −60 млн`, доли нет; When игрок подтверждает; Then цена 304,2 млн, итог для баланса −364,2 млн.
- **AC-4.2** Given у игрока доля 25 % и `C = −60 млн`; When открыто превью; Then цена `0,7 × E × 0,75`.
- **AC-4.3** Given цель «застряла» в дефолте с положительным балансом (ванильное правило 120 дней), `E = 100 млн`, `C = +900 млн`, `E_min = 27,8 млн`; When открыто превью; Then `P_f = 0,7 × (100 + 900) = 700 млн`, но цена не ниже `C⁺ + E_min = 927,8 млн`, итог −27,8 млн.

#### Additional Details

- **Complexity**: High
- **Dependencies**: FR-1, FR-7…FR-10, FR-16.
- **Assumptions**: —

### FR-5: Враждебное поглощение здоровой компании

**User Story:** Как богатый игрок, я хочу купить здорового соперника с премией, чтобы получить его рынок, продукты и заводы.

**Priority:** Must

#### Acceptance Criteria

1. WHILE компания ИИ не в дефолте и не банкрот мод SHALL предлагать поглощение по цене `P = max(P_f, C⁺ + E_min)`, где `P_f = max(E_min, m_h × (E + C⁺)) × acquisition.price × (1 − σ_игрока)`, `m_h = 1,5`, а если доля рынка цели больше доли игрока — `1,75`.
2. IF с прошлого враждебного поглощения прошло меньше `cooldownDays` (365) THEN мод SHALL показать сделку неактивной с датой, когда она станет доступна.
3. IF баланс игрока после сделки (`money + NetCash`, `NetCash = −P + C`) меньше `minCashAfter` (0) THEN мод SHALL показать сделку неактивной с недостающей суммой; покупки в кредит (с уходом баланса в минус) запрещены.
4. WHEN поглощение выполнено THEN мод SHALL принять денежный остаток цели `C`, перенести активы по FR-7…FR-9, вывести цель по FR-10, передать состояние смежных фич по FR-16 и вызвать `ModReputation.Add(игрок, −5, "acq.reputation.hostile")`.
5. WHEN считается итог сделки THEN `NetCash` SHALL быть строго отрицательным при любых `E`, `C`, `σ_игрока` и значении канала `acquisition.price`.

#### Scenarios

- **AC-5.1** Given `E = 434,6 млн`, `C = +30 млн`, доля цели 8 % при доле игрока 20 %; When игрок подтверждает; Then цена `1,5 × (434,6 + 30) = 696,9 млн`, итог −666,9 млн, репутация −5.
- **AC-5.2** Given поглощение 1985-03-01; When игрок пробует другое 1985-10-01; Then кнопка неактивна: «Доступно с 01.03.1986».
- **AC-5.3** Given `E = 200 млн`, `C = +1 000 млн`, `acquisition.price = 0,5`, доля игрока 49 %, `E_min = 27,8 млн`; When открыто превью; Then `P_f = 1,5 × 1 200 × 0,5 × 0,51 = 459 млн` меньше кэша цели, цена поднята до `C⁺ + E_min = 1 027,8 млн`, итог −27,8 млн (бесплатных денег нет).

#### Additional Details

- **Complexity**: High
- **Dependencies**: FR-1, FR-7…FR-10, FR-16; `ModReputation`.
- **Assumptions**: исход детерминирован: при выполнении условий и оплате сделка проходит. Сопротивление совета директоров может добавить `rival-personalities` через канал `acquisition.price`.

### FR-6: Покупка доли и спасение соперника

**User Story:** Как игрок, я хочу купить долю соперника (в том числе спасти его от банкротства), чтобы получать дивиденды и сохранить на рынке нужную компанию под её брендом.

**Priority:** Should

#### Acceptance Criteria

1. WHILE компания ИИ не банкрот мод SHALL предлагать купить долю `σ` из списка `[10 %, 25 %, 49 %]` так, чтобы доля игрока не превышала `maxShare = 49 %`, по цене `P_σ = σ × max(E_min, E + C) × m_s × acquisition.price` (`m_s = 1,0` для здоровой, `0,6` для компании в дефолте).
2. WHEN игрок покупает долю THEN мод SHALL списать `P_σ` с игрока (`CapitalLedger`) и добавить ту же сумму на счёт цели (`ICompany.set_MoneyAmount`) — вливание капитала, которое может вывести цель из дефолта.
3. WHEN наступает начало месяца (`TickPhase.LateMonthPassed`) THEN мод SHALL выплатить игроку дивиденд `d = σ × 0,5 × max(0, прибыль цели за прошлый месяц)` через `Company.EarnMoney(…, RevenueOrigin.Interest)`, списав `d` со счёта цели, если у цели после выплаты остаётся `≥ 0`.
4. WHEN игрок включает «Поручение на спасение» с лимитом `J_max` для компании AND эта компания доходит до вызова `AICompany.BankruptcyWarning` (его делает `BankruptcyHandler.TickBankruptcies` на 120-й день дефолта) с балансом не выше порога `ModCredit.ThresholdOf(цель)` THEN мод SHALL в prefix этого метода, до его необратимых действий (выделение GlobalFoundries у AMD-IDM, `ConsiderGoingFabless`, `SellProductionLinesToAvoidBankruptcy`), автоматически купить долю на сумму `J = −0,5 × ModCredit.DebtLimitOf(цель) − C`, если `J ≤ J_max`, у игрока хватает денег и доля не превысит `maxShare`; после вливания баланс цели строго выше порога, ванильный метод сразу выходит, а `TickBankruptcies` вызывает `CancelDefault`. Иначе мод присылает письмо «Спасти не удалось», и ванильная логика банкротства идёт как обычно.
5. IF компания, в которой у игрока доля, обанкротилась THEN мод SHALL списать долю и прислать письмо.
6. WHEN игрок покупает долю компании в дефолте THEN мод SHALL вызвать `ModReputation.Add(игрок, +3, "acq.reputation.rescue")`.

#### Scenarios

- **AC-6.1** Given здоровая цель, `E = 434,6 млн`, `C = +30 млн`; When игрок покупает 25 %; Then с игрока −116,15 млн, на счёт цели +116,15 млн, доля 25 %.
- **AC-6.2** Given доля 25 %, прибыль цели за прошлый месяц 8 млн, на счету цели 50 млн; When наступает 1-е число; Then игроку +1 млн (статья «Проценты»), у цели −1 млн.
- **AC-6.3** Given поручение с лимитом 100 млн, доли у игрока нет, оценка цели `E = 600 млн`, цель на 120-м дне дефолта с балансом −150 млн при пороге −111 млн; When вызывается `AICompany.BankruptcyWarning`; Then prefix вливает 94,5 млн (`−55,5 + 150`), доля игрока ≈ 35 % (`94,5 / ((600 − 150) × 0,6)`), баланс цели −55,5 млн выше порога, ванильный метод тут же выходит, цель не продаёт линии и не уходит в fabless, а `TickBankruptcies` вызывает `CancelDefault`.
- **AC-6.4** Given AMD (`UniqueID` 1, IDM) на 120-м дне дефолта с активным поручением; When вызывается `AICompany.BankruptcyWarning`; Then `CompanyEventHandler.TriggerSolarFoundriesSpinOff` не вызывается, линии AMD остаются.
- **AC-6.5** Given поручение с лимитом 50 млн и нужное вливание 94,5 млн; When вызывается `AICompany.BankruptcyWarning`; Then вливания нет, приходит письмо «Спасти не удалось: сумма выше лимита», ванильный метод выполняется как без мода.

#### Additional Details

- **Complexity**: High
- **Dependencies**: FR-1; `CapitalLedger` (`bankruptcy-recovery`); `ModReputation`; `ModCredit`.
- **Assumptions**: компания с долей продолжает работать под своим брендом с ванильным ИИ; управление её поведением не входит в фичу.

### FR-7: Перенос линий, технологий и опыта техпроцессов

**User Story:** Как покупатель, я хочу получить завод и технологии цели, чтобы сразу ими пользоваться.

**Priority:** Must

#### Acceptance Criteria

1. WHEN сделка FR-3/FR-4/FR-5 выполняется THEN мод SHALL сначала открыть игроку технологии цели, которых у него нет (прогресс `1` и `ResearchSector.Update(true)` до стабилизации), без лавины всплывающих окон, а для неисследованных обоими технологий поднять прогресс игрока до прогресса цели.
2. WHEN технологии перенесены THEN мод SHALL поднять опыт техпроцессов игрока до опыта цели для общих техпроцессов (`Company.OptimizeNode(узел, max(0, опыт_цели − опыт_игрока))`).
3. WHEN переносятся линии AND игрок выбрал «Забрать линии» THEN мод SHALL снять линии у цели (`AICompany.RemoveProductionLines`) и добавить их игроку на ту же пластину (`Company.ExpandFactory(N, 0, waferID)`), а затем вызвать `CompanyTypeUpdater.TriggerUpdate(true)`.
4. WHEN игрок выбрал «Продать линии» THEN мод SHALL снять линии у цели и зачислить игроку `ProductionMath.SaleCost(N, W)` через `Company.EarnMoney(…, RevenueOrigin.Sales)`.
5. IF цель производит CPU игрока (у его CPU `OutsourcedID` = `SaveID` цели) THEN мод SHALL сделать вариант «Забрать линии» обязательным.
6. WHEN превью показывает перенос линий THEN мод SHALL показать прирост ежемесячных расходов на завод (`ProductionMath.OperatingCost`) и смену типа компании игрока (например, fabless → IDM теряет скидку на разработку 33 %).

#### Scenarios

- **AC-7.1** Given у цели 40 линий на 100 мм, игрок знает 100 мм; When сделка с «Забрать линии»; Then у игрока +40 линий на 100 мм, у цели 0 линий.
- **AC-7.2** Given цель знает 150 мм, игрок нет; When сделка выполнена; Then игрок исследовал 150 мм без окон «Исследование завершено», линии на 150 мм добавлены.
- **AC-7.3** Given игрок fabless; When в превью выбрано «Забрать линии»; Then предупреждение «Компания станет IDM: скидка fabless на разработку пропадёт».

#### Additional Details

- **Complexity**: High
- **Dependencies**: спайк технологий (`tasks.md`, TSK-004).
- **Assumptions**: объекты `WaferSize` общие для всех компаний (их выдаёт `DataFinder.FindHardwareOfType`), группы линий заводов создаются для всех пластин (`Factory.InitializeLineGroups`).

### FR-8: Перенос CPU и OEM-контрактов

**User Story:** Как покупатель, я хочу получить продукты цели вместе с их контрактами, чтобы сразу получать выручку.

**Priority:** Should

#### Acceptance Criteria

1. WHEN сделка FR-4/FR-5 выполняется AND игрок — CPU-компания (`IsCpuCompany`) THEN мод SHALL перенести игроку все не снятые CPU цели семействами (база, затем варианты), сохранив названия, цены, склад, историю продаж и OEM-контракты.
2. WHEN CPU переносится THEN мод SHALL убрать его из списков ИИ (`AI.GetCpus`, `AI.GetBaseCpus`, `AI.CpusOrderedByProfit`), назначить `Cpu.Company = игрок` и добавить игроку (`Player.AddCpu`, `ProductionWindow.AddCpu`).
3. IF CPU производился на заводе цели AND линии проданы (FR-7, п. 4) THEN мод SHALL снять такой CPU (`Cpu.TriggerRetirement`) вместо переноса и показать это в превью.
4. IF игрок — литейщик без CPU-подразделения THEN мод SHALL не переносить CPU (они снимаются вместе с целью) и показать это в превью.
5. WHEN покупаются активы банкрота (FR-3) THEN мод SHALL вернуть в производство CPU из снимка (`IsRetired = false`) и перенести их по п. 2.
6. WHEN каждый CPU перенесён THEN мод SHALL вызвать `ModEvents.RaiseCpuTransferred("rival-acquisitions", цель, игрок, cpu)`; ядро поднимет `CpuTransferred` (в том числе для платформ и обзоров) и не поднимет `CpuReleased`. Во время загрузки событие не поднимается.

#### Scenarios

- **AC-8.1** Given у цели CPU «A1» и вариант «A1-L» с 2 OEM-контрактами; When поглощение выполнено; Then оба CPU в окне производства игрока, контракты в списке активных контрактов игрока, выручка по ним идёт игроку.
- **AC-8.2** Given игрок выбрал «Продать линии», CPU цели делались на её заводе; When открыто превью; Then «CPU будут сняты: A1, A1-L» и штрафы по их контрактам.
- **AC-8.3** Given сохранение и загрузка после переноса; When сейв загружен; Then CPU принадлежат игроку, вариант ссылается на базу, ошибок в `Player.log` нет.
- **AC-8.4** Given подписчик `ModEvents.CpuTransferred` и перенос семейства из 2 CPU; When сделка выполнена; Then подписчик получил 2 вызова `(цель, игрок, cpu)`, `CpuReleased` не поднят ни разу.

#### Additional Details

- **Complexity**: High
- **Dependencies**: спайк CPU (`tasks.md`, TSK-003); FR-7; `mod-framework` (`ModEvents`).
- **Assumptions**: OEM-контракт выбирает CPU по `ChosenCpuID` и продаёт от имени `cpu.Company` (`Contract.ChooseCpu`), поэтому контракты следуют за CPU. Если спайк покажет непреодолимые проблемы, FR-8 заменяется снятием CPU с компенсацией по стоимости склада (решение владельца).

### FR-9: Производственные связи и бизнес-контракты

**User Story:** Как покупатель литейщика или клиента литейщика, я хочу унаследовать его контракты и не сломать производство своих CPU.

**Priority:** Must

#### Acceptance Criteria

1. WHEN линии забираются (FR-7, п. 3) AND цель — поставщик в `BusinessContract` THEN мод SHALL переназначить такие контракты на игрока (`BusinessContract.Initialize(игрок, клиент)`), а CPU клиентов с `OutsourcedID` цели — на игрока (`Cpu.SetNewManufacturer(игрок)`).
2. WHEN переносятся контракты поставщика AND у цели был включён флаг литейных услуг (`Divisions.FoundryServices`) THEN мод SHALL включить его игроку (`Player.Instance.Company.Divisions.FoundryServices = true`, переключатель окна производства — `ProductionWindow.SetFoundryServicesToggle(true)`) и показать это в превью.
3. WHEN линии забираются AND CPU игрока производились у цели THEN мод SHALL перевести их на производство у игрока (собственное производство).
4. WHEN цель — клиент в `BusinessContract` с поставщиком-третьей стороной AND CPU цели, произведённые у этого поставщика, переносятся игроку (FR-8) THEN мод SHALL переназначить контракт на игрока как клиента (`BusinessContract.Initialize(поставщик, игрок)`; срок, наценка, штрафы и эксклюзивность сохраняются), если для эксклюзивного контракта у игрока нет другого эксклюзивного контракта в роли клиента (`BusinessContractManager.HasAnyExclusivityDeal(игрок)` = false); иначе мод SHALL не переносить контракт и перечислить его в превью как расторгаемый.
5. IF контракт заключён между игроком и целью THEN мод SHALL не переносить его: ванильный `BusinessContractManager` удалит его без штрафов, когда цель станет банкротом.
6. WHEN превью показывает контракты THEN мод SHALL перечислить переходящие контракты (поставщик или клиент, мощность, наценка, срок, эксклюзивность, штрафы `BusinessContract.ProviderFines`) и расторгаемые контракты.

#### Scenarios

- **AC-9.1** Given цель — литейщик с двумя клиентами и включённым флагом литейных услуг; When игрок забирает линии; Then оба контракта в окне бизнеса игрока как «поставщик», флаг литейных услуг включён, CPU клиентов производятся на заводе игрока.
- **AC-9.2** Given CPU игрока производились у цели; When сделка выполнена; Then эти CPU производятся на линиях игрока, расходов «Аутсорсинг» по ним больше нет.
- **AC-9.3** Given цель (fabless) — клиент литейщика с эксклюзивным контрактом, у игрока эксклюзивных контрактов как клиента нет; When игрок поглощает цель и получает её CPU; Then контракт переназначен на игрока, эксклюзивность и срок сохранены, CPU производятся у того же литейщика по контракту, а не по базовой наценке ×2.
- **AC-9.4** Given у игрока уже есть эксклюзивный контракт как у клиента с другим литейщиком; When открыто превью поглощения такой цели; Then её эксклюзивный контракт перечислен как расторгаемый.

#### Additional Details

- **Complexity**: High
- **Dependencies**: FR-7, FR-8; спайк (TSK-003, TSK-004).
- **Assumptions**: контракт поставщика работает при включённом `Divisions.FoundryServices` (проверяет спайк, но флаг в любом случае включается, если был у цели).

### FR-10: Выведение поглощённой компании без поломки ссылок

**User Story:** Как владелец, я хочу, чтобы поглощённая компания исчезала из игры штатным путём, чтобы не сломать сценарные события, сейвы и ссылки по ID.

**Priority:** Must

#### Acceptance Criteria

1. WHEN сделка FR-3/FR-4/FR-5 завершает перенос THEN мод SHALL обнулить счёт цели (`ICompany.set_MoneyAmount(0)`) и вызвать `AICompany.TriggerBankruptcy()` (отмена проектов, снятие оставшихся CPU, `IsBankrupt = true`), а затем оповестить подписчиков `BankruptcyHandler.OnCompanyWentBankrupt`.
2. Мод SHALL не удалять объект `AICompany`, не менять его `UniqueID`, `SaveID` и `Name`.
3. WHEN сейв загружается THEN поглощённая компания SHALL оставаться банкротом за счёт ванильного сохранения (`SaveObject.Company.IsBankrupt`, `AICompany.LoadBankruptcyState`) без действий мода.
4. WHILE компания поглощена мод SHALL не предлагать по ней сделок, а в окне «Сделки» показывать «Поглощена игроком (дата)».
5. WHEN мод вызывает `OnCompanyWentBankrupt` для выведенной цели THEN `RivalAcquisitionsApi.IsAbsorbedByPlayer(uniqueId)` SHALL уже возвращать `true` (запись сделки добавлена до вызова), чтобы подписчики (`scenarios-achievements`) не засчитывали поглощение как банкротство соперника; событие `RivalAcquisitionsApi.RivalBankrupt` для выведенной цели не поднимается.

#### Scenarios

- **AC-10.1** Given поглощение Texas Instruments (UniqueID 3); When открыта таблица компаний игры; Then компания отмечена банкротом, ИИ больше не выпускает CPU и не строит заводы.
- **AC-10.2** Given сейв после поглощения; When он загружен без мода; Then сейв грузится, компания банкрот, перешедшие CPU и линии у игрока.
- **AC-10.3** Given подписчик `OnCompanyWentBankrupt`, который в обработчике спрашивает `IsAbsorbedByPlayer`; When игрок поглощает соперника; Then обработчик получает `true`.

#### Additional Details

- **Complexity**: Medium
- **Dependencies**: FR-12.
- **Assumptions**: контроллеры ИИ проверяют `IsBankrupt` и перестают действовать (`AIBehaviourController`); банкрот остаётся в списках `CentralBank` и `DataFinder`, это ванильное поведение для банкротов.

### FR-11: Уведомления о дефолте и банкротстве соперников

**User Story:** Как игрок, я хочу узнавать о бедах соперников вовремя, чтобы успеть купить или спасти их.

**Priority:** Must

#### Acceptance Criteria

1. WHEN компания ИИ входит в дефолт (`BankruptcyHandler.TriggerDefault` для ИИ) во время игры THEN мод SHALL прислать письмо `ModMail` «X в дефолте: банкротство примерно через 120 дней» (приоритет `Normal`, тег `acq:default:<uniqueId>`) с многоразовыми действиями «Сделки» и (при наличии доли) «Поручение на спасение» — не больше одного письма на компанию за эпизод.
2. WHEN компания ИИ становится банкротом не по действию мода THEN мод SHALL перед ванильным `AICompany.TriggerBankruptcy` сохранить снимок её не снятых CPU (`SaveID`) и дату — для FR-3 и FR-8.
3. WHILE идёт перемотка новой игры или загрузка THEN мод SHALL не присылать писем и не открывать аукционов.

#### Scenarios

- **AC-11.1** Given соперник вошёл в дефолт; When прошёл тик; Then во «Входящих» письмо с действием «Сделки».
- **AC-11.2** Given соперник обанкротился 1987-05-03 с 3 активными CPU; When игрок покупает активы; Then все 3 CPU возвращены игроку.

#### Additional Details

- **Complexity**: Medium
- **Dependencies**: `bankruptcy-recovery` (общий патч-таргет `TriggerDefault`, ветка ИИ); `ModMail`, `ModTicks`.
- **Assumptions**: письма «Сделок» уходят с приоритетом `Normal` и подчиняются дневным лимитам `ModMail`; ID письма не хранится (поиск по тегу `ModMail.Find`).

### FR-12: Предупреждения о последствиях для сценарных компаний

**User Story:** Как игрок, я хочу знать до покупки, что поглощение изменит историю игры, чтобы не получить неожиданных эффектов.

**Priority:** Must

#### Acceptance Criteria

1. IF цель — Intel (`UniqueID` 0) или AMD (1) THEN превью SHALL предупреждать, что x86-лицензия будет отозвана (`LicenseHelper.X86LicenseHasBeenRevoked`), игроку она не передаётся, а Cyrix избавится от патентного штрафа.
2. IF цель — AMD до 2009-03-02 и GlobalFoundries ещё не появилась THEN превью SHALL предупреждать, что выделение GlobalFoundries (в коде `SolarFoundries`) не произойдёт.
3. IF цель — Intel и в игре ещё нет литейщиков THEN превью SHALL предупреждать, что Intel не откроет литейные услуги.
4. IF цель — GlobalFoundries (8) THEN превью SHALL показать, что к игроку переходит эксклюзивный контракт поставщика с AMD (если линии забираются).
5. WHEN отображаются предупреждения THEN мод SHALL требовать отдельного подтверждения «Я понимаю последствия».

#### Scenarios

- **AC-12.1** Given 1995, цель Intel; When открыто превью; Then блок «Последствия»: отзыв x86-лицензии без передачи игроку, реформа Cyrix; кнопка покупки активна только после галочки.

#### Additional Details

- **Complexity**: Low
- **Dependencies**: FR-10.
- **Assumptions**: последствия наступают ванильно, потому что цель становится банкротом (`LicenseHelper` слушает `OnCompanyWentBankrupt` и проверяет банкротов при загрузке). Покупка Intel и AMD не запрещена (решение владельца).

### FR-13: События и API для других спек

**User Story:** Как автор другой фичи, я хочу узнавать о сделках игрока и влиять на цену, чтобы соперники и сценарии реагировали на поглощения.

**Priority:** Should

#### Acceptance Criteria

1. WHEN сделка завершена THEN мод SHALL вызвать C#-событие `RivalAcquisitionsApi.DealCompleted` с записью сделки (тип, цель `UniqueID`/`SaveID`, цена, дата, что перешло).
2. WHEN меняется доля игрока или поручение THEN мод SHALL вызвать `RivalAcquisitionsApi.StakeChanged`.
3. WHEN соперник входит в дефолт или банкротится THEN мод SHALL вызвать `RivalAcquisitionsApi.RivalDefaulted` / `RivalBankrupt` (для компаний, выведенных самим модом, `RivalBankrupt` не поднимается).
4. Мод SHALL не публиковать сделки через `EventBus` и не требовать `event-system`; другие фичи подписываются на события `RivalAcquisitionsApi`.
5. Мод SHALL предоставить чтение: список сделок, доли игрока, статус «поглощена» по `UniqueID` (`IsAbsorbedByPlayer`).

#### Scenarios

- **AC-13.1** Given `rival-personalities` подписан на `DealCompleted`; When игрок поглощает соперника; Then обработчик получает запись с типом `Hostile`.

#### Additional Details

- **Complexity**: Low
- **Dependencies**: FR-3…FR-6, FR-10.
- **Assumptions**: события `RivalAcquisitionsApi` поднимает сама фича, обработчики вызываются по одному в `try/catch` (ошибка подписчика не мешает остальным); события ядра (`CpuReleased`, `CpuTransferred`) фича сама не поднимает, кроме `ModEvents.RaiseCpuTransferred`.

### FR-14: Настройки, контент, журнал и сохранение

**User Story:** Как владелец, я хочу править числа в JSON, выключать фичу и видеть историю сделок, чтобы настраивать баланс без пересборки.

**Priority:** Must

#### Acceptance Criteria

1. WHEN игра стартует THEN мод SHALL загрузить `Content/rival-acquisitions/balance.json` (`ModContent.LoadConfig`, с переопределением из `<папка игры>/PTMod/content/rival-acquisitions/`), проверить диапазоны и при ошибке использовать значения по умолчанию с записью в `ModLog`.
2. WHEN сделка выполнена THEN мод SHALL записать её в журнал сделок (`ModSave`) и показать на вкладке «История» окна «Сделки».
3. WHERE фича выключена в `ModSettings` (хаб «Моды») мод SHALL не предлагать сделок, не платить дивиденды, не исполнять поручения и не присылать писем; уже перенесённые активы остаются у игрока, а доли, аукционы и поручения хранятся в секции и возобновляются при включении (денежных обязательств перед модом у игрока нет).
4. WHEN мод удалён THEN сейв SHALL загружаться: перенесённые линии, технологии и CPU остаются у игрока (они в ванильном сейве), доли и аукционы пропадают.

#### Scenarios

- **AC-14.1** Given фича выключена; When наступает 1-е число; Then дивиденды не выплачиваются, в `Player.log` нет ошибок.

#### Additional Details

- **Complexity**: Low
- **Dependencies**: `mod-framework` (`ModContent`, `ModSettings`, `ModSave`).
- **Assumptions**: —

### FR-15: Пометка поглощённых компаний в таблице игры

**User Story:** Как игрок, я хочу видеть в ванильной таблице компаний, кого я поглотил, а не просто «банкрот».

**Priority:** Could

#### Acceptance Criteria

1. WHEN открывается таблица компаний игры (`CompaniesSpreadsheetWindow.ShowCompanies`) THEN мод SHALL заменить у поглощённых игроком компаний отметку «банкрот» на «поглощена игроком».

#### Scenarios

- **AC-15.1** Given поглощение Texas Instruments; When открыта таблица компаний; Then в колонке статуса у Texas Instruments «поглощена игроком».

#### Additional Details

- **Complexity**: Low
- **Dependencies**: FR-10.
- **Assumptions**: строки таблицы доступны после `ShowCompanies` (проверяется при реализации).

### FR-16: Передача состояния смежных фич

**User Story:** Как игрок, я хочу, чтобы вместе с компанией ко мне переходили её архитектуры и видеокарты, а не терялись из-за банкротства цели.

**Priority:** Should

#### Acceptance Criteria

1. WHEN сделка FR-3/FR-4/FR-5 выполняется AND фича `cpu-architectures` активна (`ModFeatures.IsActive`) THEN мод SHALL вызвать `ArchitectureApi.TransferCompanyState(цель, игрок, true)` (объединение исследованных семейств, максимум поддержки; привязки CPU по `SaveID` не меняются).
2. WHEN сделка FR-4/FR-5 выполняется (цель ещё не банкрот) AND фича `gpu-product-line` активна AND у цели есть GPU-подразделение (`GpuApi.IsDivisionFounded(цель)`) THEN мод SHALL вызвать `GpuApi.TransferVendorProducts(цель, игрок)` до выведения цели (иначе вендор уходит с рынка вместе с банкротом); если метод вернул `false`, мод SHALL записать в журнал сделки «GPU-линейка не передана». При покупке активов банкрота (FR-3) GPU-линейка не передаётся: вендор ушёл с рынка при банкротстве цели.
3. IF смежная фича выключена или её API недоступно THEN мод SHALL пропустить вызов, а сделку не блокировать.
4. WHEN передача состояния падает с исключением THEN мод SHALL поймать его на границе шага (`ModHooks.Guard`), пометить сделку `partial` и продолжить.

#### Scenarios

- **AC-16.1** Given `cpu-architectures` включена, у цели изучено семейство ARM, у игрока нет; When поглощение выполнено; Then у игрока семейство ARM изучено, поддержка — максимум из двух.
- **AC-16.2** Given `gpu-product-line` включена, у цели есть GPU-линейка; When поглощение (FR-5) выполнено; Then линейка числится за игроком (`GpuApi.TransferVendorProducts` вернул `true`, вызван до выведения цели).
- **AC-16.3** Given `gpu-product-line` выключена; When поглощение выполнено; Then сделка проходит без вызовов GPU.
- **AC-16.4** Given покупка активов банкрота (FR-3), у цели была GPU-линейка; When сделка выполнена; Then вызова `GpuApi.TransferVendorProducts` нет, в журнале сделки пометка.

#### Additional Details

- **Complexity**: Low
- **Dependencies**: FR-3…FR-5; мягкие: `cpu-architectures` (`ArchitectureApi`), `gpu-product-line` (`GpuApi`); `platform-generations` ничего не требует (база платформы уходит вместе с CPU по `ModEvents.CpuTransferred`).
- **Assumptions**: вызовы идут под `ModFeatures.IsActive`, жёсткой зависимости (`DependsOn`) нет.

## Non-Functional Requirements

### NFR-1: Производительность

- WHEN игрок открывает окно «Сделки» THEN мод SHALL рассчитать оценки для всех компаний не дольше 50 мс (13 компаний, ≤ 60 CPU у каждой, ≤ 250 технологий).
- WHEN наступает начало месяца THEN выплата дивидендов и проверка аукционов SHALL занимать не больше 0,5 мс.
- Мод SHALL не выполнять ежедневной работы, кроме событий банкротства (P1–P3 в design).

### NFR-2: Надёжность

- WHEN выполняется сделка THEN мод SHALL сначала построить и проверить план (чистая функция), затем выполнять шаги, а оплату провести последней; ошибка шага SHALL ловиться (`ModHooks.Guard`), логироваться, а сделка помечаться «частичной» в журнале; исключение SHALL не попасть в код игры; счётчик ошибок и `Faulted` ведёт ядро.
- IF цель не найдена по `SaveID` или её `UniqueID` не совпадает с записью THEN мод SHALL отменить сделку до первого шага.

### NFR-3: Совместимость сейвов

- Перенесённые активы SHALL храниться ванильным сейвом; `ModSave` хранит только записи сделок, доли, аукционы, снимки и поручения.
- IF секции нет THEN мод SHALL работать со значениями по умолчанию и открыть аукционы существующим банкротам (FR-3, п. 5).
- WHEN у секции `_schema` новее версии мода THEN ядро SHALL сохранить её без изменений (passthrough) и отдать фиче значения по умолчанию; фича для этого сейва не предлагает сделок. Поле версии секции пишет и читает только ядро.
- Мод SHALL не добавлять поля в классы игры.

### NFR-4: Локализация

- Все строки SHALL браться из `ModL10n` (`ru` по умолчанию, `en` — фолбэк), ключи — `acq.<область>.<имя>`; деньги — `StringFormatter.FloatToMoney`. Названия компаний берутся из игры (`ICompany.Name`).

### NFR-5: Удобство

- WHEN игрок выбирает сделку THEN мод SHALL показать полное превью (составляющие оценки, цену, принимаемый долг, баланс после, что переходит, что снимается, последствия) и потребовать двухшагового подтверждения (`ModUI.Confirm`).
- От письма до превью сделки SHALL быть не больше 2 кликов.

### NFR-6: Детерминизм

- Мод SHALL не использовать случайность: исход сделки определяется только условиями и оплатой.

### NFR-7: Безопасность данных

- Контент и `ModSave` SHALL валидироваться (доли 0…1, множители 0…10, сроки 0…3650 дней, ID ≥ 0); некорректные записи отбрасываются с `ModLog`. Сети нет.

## Edge Cases

1. **Цель обанкротилась, пока открыто окно.** Окно модальное (пауза), тик не идёт; перед исполнением план перепроверяет статус цели.
2. **Игрок не знает пластину цели и перенос технологий не сработал.** Линии добавляются на самую большую пластину игрока, не превышающую пластину цели; в журнале отметка.
3. **Цель — единственный литейщик, на котором держатся fabless-ИИ.** Если линии забраны — игрок становится их поставщиком (FR-9); если проданы — клиенты получают ванильную обработку банкротства поставщика.
4. **Игрок fabless, а цель производит его CPU.** Вариант «Продать линии» недоступен (FR-7, п. 5).
5. **Игрок — литейщик.** CPU не переносятся (FR-8, п. 4); линии и технологии переносятся; контракты клиента цели не переносятся (нет CPU, ради которых они нужны).
6. **Покупка доли у компании, которую потом поглощают.** Цена поглощения уменьшается на долю `σ`; доля закрывается.
7. **Компания с долей обанкротилась.** Доля списывается, письмо (FR-6, п. 5); открывается обычный аукцион.
8. **Поручение на спасение, но у игрока не хватает денег.** Ничего не делается, письмо «Спасти не удалось»; ванильное банкротство.
9. **Банкротства во время перемотки новой игры.** Аукционы не открываются (FR-11, п. 3); состояние ИИ, нужное к старту, фича не создаёт.
10. **Старый сейв, банкроты без снимков.** Аукцион без возврата CPU (FR-3, п. 5).
11. **Вариант CPU, база которого снята давно.** Семейство переносится целиком, база — первой (снятая база тоже переходит, чтобы ссылка `Cpu.Base` нашлась при загрузке).
12. **Огромные суммы в поздней игре.** Расчёт в `double`, в игру — `float`; цена округляется до 1 000 $.
13. **Фича выключена между сделкой и сохранением.** Активы остаются у игрока (ванильный сейв), запись в журнале — в секции, которая сохраняется как есть.
14. **Цель в дефолте, но с положительным балансом.** Ванильное правило «проверка только на 120-й день» позволяет такое состояние; цена не опускается ниже `C⁺ + E_min` (FR-4, п. 1).
15. **У игрока уже есть эксклюзивный контракт как у клиента.** Эксклюзивный контракт клиента цели не переносится и показан в превью как расторгаемый (FR-9, п. 4).
16. **Пакетный прогон «Следующий месяц».** Письма о дефолтах и банкротствах ядро показывает после `BatchEnded`; поручение на спасение исполняется на нужном дне прогона как обычно.
17. **Смежные фичи выключены или недоступны.** Передача состояния архитектур и GPU пропускается (FR-16, п. 3).
18. **Цель с поручением на спасение продана игроку целиком.** Поручение и доля закрываются вместе со сделкой.

## Constraints and Assumptions

### Technical Constraints

- Harmony (решение 0002), `ModUI` (0005), `ModSave` / `IModSaveParticipant` (0004), контент-JSON (0006). Сборка — Roslyn `csc` (0003), код `Logic` использует общее подмножество API .NET Framework 4.8 и `mscorlib` Unity (без `init`, `record`, `Index`, `Range`).
- `CompanyHelper` опознаёт компании по `UniqueID`; `DataFinder.FindCompany` — по `SaveID`; `SaveHandler.Save` собирает CPU через `DataFinder.FindOwnerOfCompany(Name)`. Поэтому объект `AICompany`, его `UniqueID`, `SaveID` и `Name` неприкосновенны.
- Приватные члены игры, к которым нужен доступ (`Cpu.manufacturer`, `Cpu.currentContract`, `ResearchSector.temporarilySupressPopup`, делегат `BankruptcyHandler.OnCompanyWentBankrupt`), проверяются самопроверкой и спайками.
- Свои патчи на `Company.AddCpu` и `AICompany.AddCpu` запрещены (резерв ядра); перенос CPU объявляется через `ModEvents.RaiseCpuTransferred`.
- Порог дефолта цели — `ModCredit.ThresholdOf(цель)` / `DebtLimitOf(цель)`; `CentralBank.DebtLimit` напрямую не читается.
- Оплата и принятие денег — через `CapitalLedger` из `bankruptcy-recovery` (капитальные операции мимо отчёта о прибылях). `CapitalLedger` не требует включённой `bankruptcy-recovery`, поэтому жёсткой зависимости (`DependsOn`) нет.
- Рыночные эффекты фича не поставляет: вклад в `market.rating.cpu` и `popularity.gain` равен 0. Канал `acquisition.price` объявлен реестром ядра (владелец — эта фича, границы [0,5; 3,0]) и только читается.

### Business Constraints

- Одиночная игра. Числа баланса — черновые множители, приняты владельцем; правятся в `balance.json`.

### Assumptions

- `D` — `ModCredit.DebtLimitOf(компания)` (ориентиры значений — в design `bankruptcy-recovery`).
- Доля рынка `MarketDataProvider.MarketShare` считается по продажам последнего дня и может «прыгать» — в оценке используется как есть.

Нет. Все вопросы v0.1 закрыты решениями владельца 2026-10-10 (таблица выше). ## Glossary

| Термин | Значение |
|---|---|
| Цель | Компания ИИ, по которой рассматривается сделка |
| Оценка `E` | Стоимость операционных активов цели для игрока: завод, технологии в разрыве, CPU, премия за долю рынка |
| `C` | Денежный остаток цели (`MoneyAmount`); отрицательный — долг; `C⁺ = max(0, C)` |
| `E_min` | Нижняя граница оценки: `0,25 × D_цели` |
| `NetCash` | Итог сделки для баланса игрока: `−P + C` (для банкрота `−P`); для полных покупок строго отрицательный |
| Аукцион | Окно времени после банкротства цели, когда можно купить её активы |
| Дистресс-покупка | Покупка компании в дефолте со скидкой и с её долгом |
| Враждебное поглощение | Покупка здоровой компании с премией |
| Доля `σ` | Миноритарная доля игрока в компании ИИ (до 49 %) |
| Поручение на спасение | Автоматическая покупка доли в момент `AICompany.BankruptcyWarning` |
| Семейство CPU | Базовый CPU и его варианты (`Cpu.Base`) |
| Выведение | Перевод поглощённой компании в банкроты штатным `AICompany.TriggerBankruptcy` |
| Сценарные компании | Компании, которые `CompanyHelper` опознаёт по `UniqueID`: Intel 0, AMD 1, Texas Instruments 3, GlobalFoundries 8, TSMC 9, Cyrix 10 (в коде игры Inlet, EMD, Texas, SolarFoundries, TCMS, Cyrux) |
| Снимок | Список `SaveID` активных CPU цели в момент банкротства |
| `CapitalLedger` | Компонент `bankruptcy-recovery` для капитальных операций и журнала |
