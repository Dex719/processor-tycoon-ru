# Обучение первого года: контент

Фича `first-year-onboarding` ведёт нового игрока по первому году письмами «Наставника» в почте игры. Шаги, условия, тексты и ритм письма лежат в JSON, поэтому их можно править без пересборки `PTMod.dll`. Этот файл описывает форматы, условия, плейсхолдеры и способ переопределить контент. Всё, что здесь написано, проверяют тесты фичи: пример из раздела «Пример» проходит ту же проверку, что и встроенные шаги.

## Для игроков

- **Включить или выключить обучение.** В окне новой игры нажмите «Моды…»: там переключатель «Обучение». По умолчанию он включён, пока вы ни разу не завершали и не пропускали обучение; дальше стоит ваш последний выбор.
- **Управлять обучением в игре.** Хаб «Моды» → «Обучение»: режим, трек, «Шаг N из M» и четыре кнопки: «Повторить письмо шага», «Пропустить шаг», «Пропустить обучение», «Перезапустить обучение». Те же кнопки «Пропустить шаг» и «Пропустить обучение» есть в самих письмах.
- **Две настройки** в хабе «Моды» (у фичи «Обучение первого года»): «Пауза при новом шаге» (игра встаёт на паузу, когда приходит письмо нового шага) и «Подсказки-напоминания» (Наставник напоминает о себе, если вы долго стоите на одном шаге).
- **Прогресс хранится в сохранении.** Загрузили сейв из середины обучения: письма продолжатся с того же места, дубликатов не будет. Сейв, сделанный до установки мода, обучения не запускает; в хабе его можно запустить кнопкой «Перезапустить обучение».
- **Свои тексты и шаги.** См. «Как переопределить контент». Ломать ничего не нужно: если запись в вашем файле неверна, мод пропустит её, напишет причину в `Player.log` и продолжит со встроенными шагами.

## Какие файлы и где они лежат

| Что | Встроенный файл (в `PTMod.dll`) | Для чего |
|---|---|---|
| Шаги и советы | `content/first-year-onboarding/steps.json` | Какие письма и когда приходят |
| Ритм | `content/first-year-onboarding/config.json` | Срок обучения, пауза между письмами, запасное число дней |
| Тексты | `l10n/ru/first-year-onboarding.json`, `l10n/en/first-year-onboarding.json` | Заголовки, тела писем, подсказки, кнопки, хаб |

Исходники встроенных файлов: `mod/src/PTMod/Content/first-year-onboarding/` и `mod/src/PTMod/L10n/<язык>/first-year-onboarding.json`.

## Как переопределить контент

Ваши файлы лежат в папке игры и накладываются поверх встроенных. Папку `PTMod` создайте сами, если её нет.

| Что переопределяется | Путь |
|---|---|
| Шаги | `<папка игры>/PTMod/content/first-year-onboarding/steps.json` |
| Ритм | `<папка игры>/PTMod/content/first-year-onboarding/config.json` |
| Тексты, русский | `<папка игры>/PTMod/l10n/ru/first-year-onboarding.json` |
| Тексты, английский | `<папка игры>/PTMod/l10n/en/first-year-onboarding.json` |

Правила слияния:

- **`steps.json`** имеет вид `{ "schema": 1, "records": [ ... ] }`. Запись с `id` встроенного шага **заменяет его целиком** (поля не сливаются, запись должна быть полной). Запись с новым `id` добавляет шаг. Запись `{ "id": "...", "disabled": true }` убирает встроенный шаг; остальные поля такой записи не читаются.
- **Неверная запись** не вытесняет встроенный шаг: она пропускается, а причина попадает в `Player.log` (`[first-year-onboarding] WARN ... step 'x' skipped: ...`). Остальные записи грузятся.
- **Файл целиком** игнорируется, если у него другая `schema`, синтаксическая ошибка или нет массива `records`; тогда работает встроенный.
- **`config.json`** сливается по полям: достаточно указать только то, что меняете. Числа вне допустимого диапазона приводятся к границе диапазона с предупреждением в логе.
- **Тексты** — плоский JSON `{ "ключ": "текст" }`. Ключ из вашего файла заменяет встроенный текст, новый ключ добавляется. Для нового шага нужен текст хотя бы в одном языке; русский основной, английский запасной, лучше написать оба.
- Переопределения читаются при старте игры. После правки перезапустите игру.
- Если отключить (`disabled`) все последовательные шаги трека, обучение для этого трека выключится, а хаб покажет «Контент обучения повреждён — см. Player.log». Оставьте у каждого трека хотя бы один последовательный шаг.

## config.json

```json config-example
{ "schema": 1, "tutorialWindowDays": 365, "minDaysBetweenMails": 2, "defaultDaysFallback": 120 }
```

| Поле | По умолчанию | Диапазон | Смысл |
|---|---|---|---|
| `schema` | 1 | равно 1 | Версия формата файла. Другое значение: файл переопределения игнорируется |
| `tutorialWindowDays` | 730 | 30..3650 | Через сколько игровых дней от старта обучение заканчивается итоговым письмом, даже если не все шаги сделаны |
| `minDaysBetweenMails` | 1 | 1..365 | Наименьшее число игровых дней между двумя письмами обучения. Не больше одного письма в игровой день |
| `defaultDaysFallback` | 120 | 1..3650 | Сколько дней в дефолте называют письма, если игра не отдала своё число (`BankruptcyHandler.defaultTimeLimit`) |

## steps.json: поля шага

Запись шага — объект. Неизвестные поля игнорируются.

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `id` | строка | обязательно | Уникальный идентификатор: `[a-z0-9_]{2,40}`. По нему переопределяют шаги, на него ссылаются тексты (`onb.<id>.name`, `onb.<id>.done`) и условие `onb.stepDone` |
| `order` | число | 0 | Место среди последовательных шагов трека, 1..9999, уникально внутри трека. Для ситуативного совета не используется |
| `kind` | `"sequential"` или `"situational"` | `"sequential"` | Шаг трека или ситуативный совет |
| `tracks` | список строк | обязательно | Треки: подмножество `"idm"`, `"fabless"`, `"foundry"`. Шаг приходит только игроку этих треков |
| `showWhen` | условие | нет | Шаг становится текущим (совет отправляется) только когда условие истинно. У совета обязательно |
| `completeWhen` | условие | нет | Шаг выполнен, когда условие истинно (выполненное не отменяется). Нужно ровно одно из `completeWhen` и `completeOnShow` |
| `completeOnShow` | `true`/`false` | `false` | Информационный шаг: выполнен в тот момент, когда отправлено письмо |
| `streakDays` | число | 0 | Для совета: условие `showWhen` должно держаться столько игровых дней подряд, 0..365. 0 — сразу |
| `priority` | `"critical"`, `"normal"`, `"low"` | `"normal"` | Приоритет письма в очереди ядра |
| `pauseOnShow` | `true`/`false` | `false` | Ставить игру на паузу, когда письмо дошло до ящика (если включена настройка «Пауза при новом шаге» и время идёт) |
| `mail` | объект | обязательно | Содержимое письма, см. ниже |
| `reminders` | список | пусто | Подсказки, которые приходят, если шаг долго не выполняется |
| `disabled` | `true`/`false` | `false` | Только в файле переопределения: убрать встроенный шаг с этим `id` |

Поля `mail`:

| Поле | Тип | Смысл |
|---|---|---|
| `titleKey` | строка | Ключ заголовка. Русская строка начинается с `[Наставник]`, английская — с `[Mentor]` |
| `bodyKey` | строка | Ключ тела письма. Вариант для трека — ключ `<bodyKey>.<трек>` (например `onb.production.body.fabless`): он используется, если такой ключ есть |
| `args` | список строк | Имена плейсхолдеров по порядку: `{0}`, `{1}`... в заголовке и теле. См. «Плейсхолдеры» |
| `buttons` | список строк | Кнопки письма. См. «Кнопки письма» |
| `variants` | список `{ "when": условие, "bodyKey": ключ }` | Тело по условию в момент отправки; побеждает первый вариант с истинным условием. Так сделан совет про дефолт: текст другой, если включена фича `bankruptcy-recovery` |

Поля записи в `reminders`:

| Поле | Тип | Смысл |
|---|---|---|
| `afterDays` | число | Через сколько игровых дней после доставки письма показать подсказку, 1..3650; в списке строго по возрастанию |
| `hintKey` | строка | Ключ текста подсказки |
| `args` | список строк | Плейсхолдеры подсказки (как в `mail.args`) |

Каждая подсказка показывается один раз и не больше одной в игровой день. Когда подсказки кончились, кнопка «Подсказка» в письме становится неактивной.

## Как работают шаги

- **Треки.** Игра определяет трек по компании игрока: `idm` (компания сама проектирует и производит CPU), `fabless` (проектирует CPU, но не производит), `foundry` (производит для других). Если компания сменила тип, обучение переходит на другой трек на границе шагов; шаги чужого трека помечаются «не применимо».
- **Последовательные шаги** идут строго по `order`, по одному текущему шагу. Письмо приходит не чаще раза в игровой день и не раньше `minDaysBetweenMails` после предыдущего; следующий шаг не отправляется, пока письмо предыдущего не дошло до ящика.
- **«Уже сделано».** Если игрок опередил обучение и условие шага уже истинно, письмо этого шага не отправляется, а шаг перечисляется строкой «Уже сделано: ...» в следующем письме (фраза берётся из ключа `onb.<id>.done`).
- **`showWhen` у последовательного шага** задерживает его, а вместе с ним и шаги после него.
- **Закрывающий шаг** имеет `id` `graduation`. Его письмо — итоговое: заголовок и текст из `mail`, а под ним список всех шагов с их статусами. Обучение завершается, когда шаг `graduation` отправлен или вышел срок `tutorialWindowDays`.
- **Ситуативные советы** (`kind: situational`) отправляются один раз за игру, когда `showWhen` истинно (при `streakDays` > 0 — столько дней подряд). Совет не обгоняет письмо шага: в игровой день уходит не больше одного письма обучения. Советов не касается список «Уже сделано».
- **Массовая прокрутка.** Во время загрузки, перемотки новой игры и прогона месяца за один кадр письма не отправляются и условия не читаются. После прогона месяца приходит не больше одного письма.
- **Банкротство** игрока прекращает обучение без итогового письма.

## Условия

Условия записываются в нотации ядра мода (`ModConditions`):

- Предикат: `{ "type": "имя", ...параметры }`.
- Все условия сразу: `{ "all": [ условие, условие ] }`. Любое из условий: `{ "any": [ ... ] }`. Отрицание: `{ "not": условие }`.

Лишние и неизвестные параметры — ошибка; запись с такой ошибкой пропускается. Предикаты, которые говорят о компании, принимают необязательный параметр `company` (`"player"`, `"ai:<номер>"`, а там, где разрешено, `"anyAI"`); без него речь идёт о компании игрока. Предикаты фичи называются с префиксом `onb.`.

## Предикаты onb.\*

Эти предикаты регистрирует сама фича. Они читают публичное состояние игры без патчей и дёшевы: их вычисляют два раза в секунду, и только для текущего шага и ситуативных советов.

| Предикат | Параметры | Истинно, когда |
|---|---|---|
| `onb.cpuProjectActive` | — | У игрока идёт проект разработки CPU |
| `onb.factoryProjectActive` | — | Идёт проект расширения фабрики |
| `onb.producedToday` | — | Вчера выпущен хотя бы один CPU игрока |
| `onb.soldToday` | — | Вчера продан хотя бы один CPU игрока |
| `onb.missedOverSold` | — | Вчера упущенных продаж больше, чем проданного |
| `onb.anyOldCpu` | — | Есть выпущенный CPU, который игра считает устаревшим |
| `onb.oemAvailable` | — | Есть OEM-контракты, по которым можно отправлять предложения |
| `onb.automate` | — | Включена автоотправка предложений по контрактам |
| `onb.foundryServices` | — | Компания игрока открыла литейные услуги |
| `onb.isJan1` | — | Сегодня 1 января |
| `onb.dayOfMonth` | `day` (1..31) | Сегодня указанное число месяца |
| `onb.stepDone` | `id` | Шаг с таким `id` закрыт: выполнен или пропущен игроком |

## Плейсхолдеры в письмах

Имена из `args` подставляются в `{0}`, `{1}`... по порядку. Значения фиксируются в момент отправки письма; деньги записаны так, как их пишет сама игра.

| Имя | Что подставляется |
|---|---|
| `highEndBudget` | Бюджет сегмента High End (`Market.get_HighEndBudget`) |
| `midRangeBudget` | Бюджет сегмента Mid Range |
| `lowEndBudget` | Бюджет сегмента Low End |
| `industriesBudget` | Бюджет сегмента Industries |
| `debtLimit` | Кредитный лимит игрока (`ModCredit.PlayerDebtLimit()`, с учётом множителя `bank.creditLimit`) |
| `defaultDays` | Сколько дней компания может быть в дефолте (`BankruptcyHandler.defaultTimeLimit`, иначе `defaultDaysFallback`) |
| `money` | Деньги игрока |
| `company` | Название компании игрока |
| `founder` | Имя основателя |

Другие имена — ошибка записи (шаг пропускается). Индекс `{n}` в русском тексте не должен выходить за длину `args`. Если значение не удалось прочитать, письмо покажет `?` вместо него, а в логе будет предупреждение.

## Кнопки письма

| Идентификатор | Что делает |
|---|---|
| `skipStep` | Пропустить шаг (срабатывает один раз) |
| `skipAll` | Пропустить всё обучение (срабатывает один раз) |
| `hint` | Показать следующую подсказку шага; серая, если у шага нет подсказок или они кончились |
| `openCpuDesigner` | Открыть конструктор CPU; письмо остаётся открытым |
| `openFactoryExpansion` | Открыть окно расширения фабрики; письмо остаётся открытым |

## Тексты

- Все тексты берутся из `ModL10n` по ключам с префиксом `onb.`. Русский — основной язык, английский — запасной. Без ключа письма нет: в тексте появится `[ключ]`.
- Для шага `<id>` нужны ключи, которые вы назвали в `mail` и `reminders`, а для последовательного шага ещё `onb.<id>.name` (короткое название для хаба и итогового письма) и, если у шага есть `completeWhen`, `onb.<id>.done` (фраза для строки «Уже сделано»). Названия ключей по схеме `onb.<id>.title`, `onb.<id>.body`, `onb.<id>.hint1` — только соглашение.
- Заголовок начинается с `[Наставник]` (по-английски `[Mentor]`); без него будет предупреждение.
- Тело письма: 3–6 коротких абзацев, не больше 1200 символов (иначе предупреждение: письмо должно читаться без прокрутки), последний абзац — `<b>Что сделать сейчас:</b>` и одно действие. Числа лучше брать из плейсхолдеров, а не писать вручную.
- Разметка — теги текста игры (`<b>...</b>`). Абзацы разделяйте `\n\n`.

## Если что-то не работает

- Откройте `Player.log` и найдите строки с `[first-year-onboarding]`. Причина пропуска шага написана по-английски: `step 'x' skipped: completeWhen.type: unknown predicate 'researchActve'`.
- Итог проверки при старте — строка `self-check: OK` или список проблем (члены игры, предикаты `onb.*`, каталог шагов, русские ключи).
- В отладочной сборке можно включить замер времени опроса: в `ptmod_settings.json` в разделе `debug` поставьте `"first-year-onboarding.perf": true`. Раз в игровой месяц в `Player.log` пишутся среднее и максимум времени `Poll` и `OnGameDay`.
- `python install.py --check` проверяет файлы текстов (ключи `ru` и `en`, префиксы); игра при этом не нужна.
