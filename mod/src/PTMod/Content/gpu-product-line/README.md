# Видеокарты: контент

Фича `gpu-product-line` (окно «Видеокарты») берёт все числа, части, сегменты рынка, производителей и консольные предложения из JSON-файлов. Их можно править без пересборки `PTMod.dll`. Этот файл описывает формат каждого поля с единицами, правила переопределения и примеры. Всё, что здесь написано, проверяют тесты фичи: каждое поле контента названо в таблицах ниже, а примеры из раздела «Примеры» проходят ту же проверку, что и встроенные файлы.

## Для игроков

- Как начать, как копировать сейв и что делают переключатели, написано в разделе «Видеокарты» главного [README](../../../../../README.md).
- Свои правки лежат в папке игры (`<папка игры>/PTMod/content/gpu-product-line/`) и накладываются поверх встроенных файлов. Ломать ничего не нужно: неверная запись пропускается, причина попадает в `Player.log`, остальное работает.
- Файлы читаются при запуске игры. После правки перезапустите игру.

| Что | Встроенный файл (в `PTMod.dll`) | Вид | Для чего |
|---|---|---|---|
| Архитектуры | `content/gpu-product-line/architectures.json` | записи | Что умеет кристалл: блоки, частота, функции |
| Видеопамять | `content/gpu-product-line/memory.json` | записи | Типы памяти: скорость, цена, разрядность шины |
| Охлаждение | `content/gpu-product-line/coolers.json` | записи | Системы охлаждения |
| Дерево исследований | `content/gpu-product-line/research.json` | записи | Узлы лаборатории: какая часть, когда, за сколько |
| Сегменты рынка | `content/gpu-product-line/segments.json` | записи | Покупатели, бюджет, требования |
| Эпохи | `content/gpu-product-line/eras.json` | записи | Начало эр рынка и их письма |
| Производители | `content/gpu-product-line/vendors.json` | записи | Именные соперники |
| Консольные предложения | `content/gpu-product-line/consoles.json` | записи | Заказы производителей консолей |
| Таймлайн | `content/gpu-product-line/timeline.json` | объект | Техпроцесс и наибольший кристалл по годам |
| Баланс | `content/gpu-product-line/balance.json` | объект | Все числа экономики |
| Тексты | `l10n/ru/gpu-product-line.json`, `l10n/en/gpu-product-line.json` | плоский объект | Названия, письма, подсказки |

Исходники встроенных файлов: `mod/src/PTMod/Content/gpu-product-line/` и `mod/src/PTMod/L10n/<язык>/gpu-product-line.json`.

## Как переопределить контент

Положите файл с тем же именем в `<папка игры>/PTMod/content/gpu-product-line/`. Папку `PTMod` создайте сами, если её нет.

**Файлы записей** (`architectures`, `memory`, `coolers`, `research`, `segments`, `eras`, `vendors`, `consoles`) имеют вид:

```json
{ "schema": 1, "records": [ { "id": "...", "...": "..." } ] }
```

- `schema` у файла записей всегда `1` (это версия формата контента, а не сейва). Файл с другой `schema`, с синтаксической ошибкой или без массива `records` игнорируется целиком, и работает встроенный.
- Запись с `id` встроенной записи **заменяет её целиком**: поля не сливаются, запись должна быть полной. Скопируйте встроенную запись и измените нужное поле.
- Запись с новым `id` добавляется в конец.
- Запись `{ "id": "...", "disabled": true }` убирает встроенную запись. Остальные поля такой записи не читаются.
- Неверная запись не вытесняет встроенную: она пропускается, а причина попадает в `Player.log` (`[gpu-product-line] ...`). Остальные записи грузятся.
- Повторный `id` внутри одного файла: используется первая запись, в логе предупреждение.

**Файлы-объекты** (`balance`, `timeline`) сливаются поле за полем, с заходом во вложенные объекты: достаточно указать только то, что меняете. Массивы и числа вашего файла заменяют встроенные. `schema` — тоже `1`.

**Тексты** — плоский JSON `{ "ключ": "текст" }` в `<папка игры>/PTMod/l10n/ru/gpu-product-line.json` и `.../en/gpu-product-line.json`. Ключ из вашего файла заменяет встроенный, новый ключ добавляется. Все ключи этой фичи начинаются с `gpu.`.

## Общие правила

- **Деньги** — деньги игры; числа в контенте даны без инфляции, она применяется там, где сказано (основание подразделения, проекты).
- **Годы** — календарные годы, от 1971 до 2040. `0` в полях `closesYear`, `exitYear`, `mergeYear` значит «никогда» или «нет».
- **Десятилетия.** Поля `sizeByDecade` и `budgetByDecade` — ровно 7 чисел: 1970-е, 1980-е, 1990-е, 2000-е, 2010-е, 2020-е, 2030-е. Внутри десятилетия значение плавно переходит к следующему, как множители населения в игре.
- **Идентификаторы** (`arch.*`, `vram.*`, `cool.*`, id сегментов, эр, производителей и консольных предложений) — локальные имена файлов этой фичи: латиница, цифры, `.`, `_`, `-`. К ключам текстов, предикатам и событиям они не относятся.
- **Тексты.** Название части, сегмента или эры — ключ текста `nameKey` с префиксом `gpu.`. Если текста с таким ключом нет, игроку показывается `id`. Название производителя — объект `{ "ru": "...", "en": "..." }`.
- **Техпроцессы** называются точно, как в игре (`ProcessNode.Name`): `350nm`, `1.5µm`, `90nm`.
- **Технологии игры** в `requiresGameTechs` называются точно, как в игре (`Technology.Name`): `DDR2`, `130nm`.
- **Компании** — ключом `ai:<UniqueID>`: AMD это `ai:1`, Intel это `ai:0`. Показанное имя привязанного производителя берётся из игры.
- **Функции архитектуры** (`features`) — короткие имена: `2d`, `gui`, `3d`, `tnl`, `shader`, `unified`, `compute`, `rt`, `tensor`. Текст функции — ключ `gpu.feat.<имя>`. Своё имя функции можно добавить, если сегмент потребует её в `featureReqs`.
- **Мегагерцы и килобайты.** Частота видеокарты в МГц, память в МБ, шина в битах, площадь кристалла в мм², мощность в ваттах, температура в °C.

## architectures.json

Что умеет кристалл архитектуры. Формулы: число блоков `S = max(1, floor(T / transistorsPerUnit))`, мощность `C = S × частота × opsPerClock`, упор в память `B / (C × bytesPerOp)`.

| Поле | Тип | Единицы | Смысл |
|---|---|---|---|
| `id` | строка | — | Уникальное имя записи, например `arch.3d`. Обязательное |
| `nameKey` | строка | ключ текста | Название в окне. Обязательное, префикс `gpu.` |
| `year` | число | год | Год появления архитектуры. Соперники берут последнюю архитектуру, у которой `year` не позже их года |
| `transistorsPerUnit` | число | транзисторов на блок | Сколько транзисторов в одном блоке. Больше нуля. Чем больше, тем меньше блоков на кристалле |
| `opsPerClock` | число | операций за такт на блок | От 1 до 1000 |
| `clockRatio` | число | доля частоты CPU | Наибольшая частота карты как доля максимальной частоты процессора компании. От 0.001 до 2 |
| `bytesPerOp` | число | байт на операцию | Сколько байт обмена с памятью нужно на одну операцию. Больше нуля |
| `powerCoef` | число | Вт на (мм² × МГц) | Коэффициент мощности. Больше нуля |
| `complexity` | число | доля | Вклад сложности в процент брака: от 0 до 10 |
| `dieMaterialCost` | число | деньги за кристалл | Материал кристалла в себестоимости. Не меньше нуля |
| `projectCost` | число | деньги | Стоимость разработки архитектуры в проекте |
| `projectDays` | целое | дни | Срок разработки архитектуры, от 1 до 3650. Складывается со сроком памяти |
| `features` | список строк | имена функций | Функции, которые есть у карты. Сегменты рынка требуют их |

## memory.json

| Поле | Тип | Единицы | Смысл |
|---|---|---|---|
| `id` | строка | — | Например `vram.gddr3`. Обязательное |
| `nameKey` | строка | ключ текста | Название в окне |
| `year` | число | год | Год появления. От него считается удешевление |
| `dataRateMTs` | число | МТ/с на линию шины | Скорость передачи. Пропускная способность `B = разрядность / 8 × dataRateMTs` (МБ/с). Больше нуля |
| `costPerMB` | число | деньги за МБ | Себестоимость мегабайта в год `year`. Не меньше нуля |
| `costDecayPerYear` | число | множитель в год | Ежегодное удешевление: цена × множитель в степени «лет с `year`». От 0.001 до 1 |
| `costFloor` | число | доля от начальной цены | Ниже этого удешевление не идёт. От 0 до 1 |
| `maxVramMB` | число | МБ | Наибольший объём памяти этого типа. Больше нуля |
| `busWidths` | список целых | биты | Допустимая разрядность шины. Не пуст, каждое значение больше нуля. Игрок выбирает одно, соперник берёт по номеру `rivalBusTier` |
| `projectCost` | число | деньги | Стоимость разработки в проекте |
| `projectDays` | целое | дни | Срок разработки, от 1 до 3650 |

## coolers.json

| Поле | Тип | Единицы | Смысл |
|---|---|---|---|
| `id` | строка | — | Например `cool.fan`. Обязательное |
| `nameKey` | строка | ключ текста | Название в окне |
| `year` | число | год | Год появления |
| `thermalResistance` | число | °C на ватт | Температура карты `ambientC + мощность × thermalResistance` (`ambientC` в `balance.json`). Меньше значит холоднее. Больше нуля |
| `cost` | число | деньги за карту | Цена охлаждения в себестоимости. Не меньше нуля |

## research.json

Узлы лаборатории: по одному на часть, которую нужно изучить, чтобы она появилась в конструкторе.

| Поле | Тип | Единицы | Смысл |
|---|---|---|---|
| `id` | строка | — | Имя узла. Обычно совпадает с `id` части |
| `branch` | строка | `architecture`, `memory` или `cooling` | Ветка дерева и файл, в котором лежит открываемая часть |
| `unlocks` | строка | `id` части | Часть, которую узел открывает (из файла своей ветки) |
| `year` | число | год | Год узла. Раньше этого года срок исследования растёт на 350 % за год, позже (через год) уменьшается на 15 % в год, но не больше чем на 75 % |
| `baseDays` | целое | дни | Срок исследования при финансировании 100 % без поправок по году. От 1 до 3650 |
| `monthlyCost` | число | деньги в месяц | Расход при финансировании 100 %, до множителя канала `research.cost`. От 0 до 1e12 |
| `requiresNodes` | список строк | `id` узлов | Узлы, которые нужно изучить раньше. Ссылки на несуществующие узлы и циклы запрещены |
| `requiresGameTechs` | список строк | имена технологий игры | Технологии игры, которые компания должна изучить. В окне узел покажет «Нужно: ...» |

## segments.json

Сегмент рынка видеокарт: сколько в нём покупателей, сколько они готовы платить и чего требуют. Рынок работает в одном из двух режимов (`marketMode` в `balance.json`), и у каждого сегмента в поле `mode` указано, к какому он относится. Встроенный режим `eras` использует шесть сегментов, режим `single` один (`consumer`).

| Поле | Тип | Единицы | Смысл |
|---|---|---|---|
| `id` | строка | — | Например `gaming.mid`. Обязательное |
| `mode` | строка | `single` или `eras` | В каком режиме рынка сегмент существует. Обязательное |
| `nameKey` | строка | ключ текста | Название в окне |
| `opensYear` | число | год | Когда сегмент открывается. Обязательное |
| `closesYear` | число | год | Когда закрывается; `0` — никогда. Не раньше `opensYear` |
| `baseSize` | число | покупателей в год | Размер рынка при множителе 1. Покупателей в день `N = baseSize × множитель десятилетия / 365`. Обязательное |
| `sizeByDecade` | 7 чисел | множитель | Размер рынка по десятилетиям, 1970-е ... 2030-е. Обязательное |
| `budgetByDecade` | 7 чисел | деньги | Сколько покупатель готов заплатить за карту, по десятилетиям. Обязательное. Больше нуля |
| `consumptionTarget` | число | ватты | Целевая мощность: карты экономнее набирают рейтинг по потреблению (`consumptionTarget / мощность карты`). Больше нуля |
| `wPerf` | число | вес | Вес производительности в рейтинге |
| `wUnder` | число | вес | Как сильно цена ниже бюджета повышает рейтинг |
| `wOver` | число | вес | Как сильно цена выше бюджета снижает рейтинг. При цене от трёх бюджетов карту не покупают |
| `wObs` | число | вес | Как сильно отставание от самой быстрой карты снижает рейтинг |
| `wCons` | число | вес | Вес потребления энергии в рейтинге; `0` — покупателям всё равно |
| `missingFeatureFactor` | число | множитель, 0–1 | Во сколько раз падает рейтинг за каждую требуемую функцию, которой нет у карты. `0` — такая карта в сегменте не продаётся |
| `featureReqs` | список `{ "year", "f" }` | год, имена функций | С года `year` сегмент требует функции `f` (действует запись с наибольшим годом, не позже текущего) |
| `vramReq` | список `{ "year", "v" }` | год, МБ | Объём видеопамяти, которого ждёт сегмент, в контрольные годы. Между годами растёт по экспоненте. Карта с меньшим объёмом теряет рейтинг, но не больше чем в четыре раза |
| `rivalDieShare` | число | доля, 0–1 | Какую долю наибольшего кристалла года (`maxDieByYear`) берут карты соперников |
| `rivalVramFactor` | число | множитель | Во сколько раз память карт соперников больше требования сегмента |
| `rivalBusTier` | целое | номер, 0–16 | Какую разрядность шины берут соперники: `busWidths[min(rivalBusTier, число значений - 1)]` |

## eras.json

Эры рынка работают только в режиме `eras`. Начало эры приходит письмом.

| Поле | Тип | Единицы | Смысл |
|---|---|---|---|
| `id` | строка | — | Например `era.3d`. Обязательное |
| `startYear` | число | год | Год начала эры. Обязательное |
| `nameKey` | строка | ключ текста | Название эры (заголовок письма и плашка во вкладке «Рынок») |
| `mailKey` | строка | ключ текста | Текст письма об эре |
| `hintNodes` | список строк | `id` узлов | Узлы дерева, которые письмо советует изучить |

## vendors.json

Именные производители. Игра не создаёт для них компаний: это данные, по которым фича выпускает карты на рынок. Производитель, привязанный к компании ИИ, платит за разработку и производство деньгами этой компании.

| Поле | Тип | Единицы | Смысл |
|---|---|---|---|
| `id` | строка | — | Например `nvidia`. Обязательное |
| `name` | объект `{ "ru", "en" }` | текст | Запасное название. Обязательно для производителя, который может быть виртуальным |
| `series` | строка | название | Серия для названий карт: «`series` N», где N — число выпущенных карт (Voodoo 3, GeForce 2) |
| `bindTo` | строка | ключ компании | `""` — виртуальный производитель; `ai:<UniqueID>` — привязан к компании ИИ (AMD `ai:1`, Intel `ai:0`) |
| `fallbackVirtual` | да/нет | — | Если компании нет в партии или она обанкротилась, производитель продолжает как виртуальный. Без `bindTo` смысла не имеет |
| `entryYear` | число | год | Год выхода на рынок. Обязательное |
| `exitYear` | число | год | Год ухода; `0` — не уходит |
| `mergeYear` | число | год | Год слияния; `0` — нет. Нужен вместе с `mergeInto` |
| `mergeInto` | строка | `id` производителя | Кто его поглощает: карты и узнаваемость переходят поглотителю |
| `techLag` | число | годы | Отставание его технологий от переднего края. От 0 до 30 |
| `priceFactor` | число | множитель | Цена карты как доля бюджета сегмента |
| `capacityShare` | число | доля, 0–1 | Выпуск в день как доля покупателей главного сегмента |
| `strength` | число | от 0 до 10 | Сила марки: от неё зависит стартовая популярность новых карт |
| `designIntervalMonths` | целое | месяцы | Как часто выходит новая карта (к сроку добавляется 0-3 месяца). От 1 до 240 |
| `segments` | список строк | `id` сегментов | Где продаёт. Сегменты другого режима рынка пропускаются |
| `color` | строка | `#RRGGBB` | Цвет в долях рынка |

## consoles.json

Предложения производителей консолей (фича «Консольные заказы»). Предложение приходит письмом в год `offerYear`, если подразделение основано и переключатель «Консольные заказы» включён. Общие числа заказа — блок `console` в `balance.json`.

| Поле | Тип | Единицы | Смысл |
|---|---|---|---|
| `id` | строка | — | Например `sony.2`. Заказ создаётся один раз на предложение. Обязательное |
| `clientKey` | строка | ключ текста | Название производителя консоли, например `gpu.console.client.sony`. Префикс `gpu.`. Обязательное |
| `offerYear` | число | год | В какой год приходит письмо. От 1981 до 2040. Обязательное |
| `termYears` | целое | годы | Срок заказа после принятия. От 1 до 15. Обязательное |

## timeline.json

| Поле | Тип | Единицы | Смысл |
|---|---|---|---|
| `nodeByYear` | список `{ "year", "node" }` | год, имя техпроцесса | Какой техпроцесс считается передним с года `year`. По нему делают карты фон и виртуальные производители. Имя точное, как в игре. Неизвестное имя пропускается |
| `maxDieByYear` | список `{ "year", "v" }` | год, мм² | Наибольший кристалл года. Между контрольными годами значение растёт плавно |

Поля вложенных записей: `year` и `node` у `nodeByYear`; `year` и `v` у `maxDieByYear`, `vramReq`; `year` и `f` у `featureReqs`; `ru` и `en` у текста `name`.

## balance.json

Все числа экономики. Каждое поле необязательно: что не указано, берётся встроенное. Число вне допустимого диапазона заменяется встроенным, в `Player.log` строка о нём.

**Верхний уровень**

| Поле | Единицы | Смысл |
|---|---|---|
| `marketMode` | `single` или `eras` | Режим рынка: один сегмент `consumer` или шесть сегментов эр. Встроенный: `eras` |

**`market`**

| Поле | Единицы | Смысл |
|---|---|---|
| `opensYear` | год | Год открытия рынка видеокарт. До него подразделение основать нельзя |

**`founding`** — основание подразделения

| Поле | Единицы | Смысл |
|---|---|---|
| `cost` | деньги | Стоимость основания до поправки на инфляцию |
| `catchUpLagYears` | годы | Узлы дерева с годом не позже «текущий год минус это число» открываются бесплатно |

**`research`** — лаборатория

| Поле | Единицы | Смысл |
|---|---|---|
| `penaltyPerYear` | доля на год | Рост срока исследования за каждый год до года узла (3.5 = +350 %) |
| `bonusPerYear` | доля на год | Уменьшение срока за каждый год после года узла (0.15 = -15 %) |
| `maxBonus` | доля | Наибольшее уменьшение срока (0.75 = не больше -75 %) |
| `fundingMin`, `fundingMax` | доля | Границы ползунка финансирования |
| `queueMax` | узлы | Длина очереди исследований |

**`design`** — конструктор

| Поле | Единицы | Смысл |
|---|---|---|
| `minDie` | мм² | Наименьшая площадь кристалла |
| `clockMinShare` | доля | Наименьшая частота как доля наибольшей |
| `bandwidthExponent` | степень | Как сильно упор в память режет производительность |
| `bandwidthRatioMin` | доля | Нижний предел отношения пропускной способности к потребности |
| `densityExponent` | степень | Как плотность техпроцесса влияет на мощность (-0.25) |
| `basePowerW` | Вт | Постоянная часть мощности |
| `ambientC` | °C | Температура окружения |
| `safeTempC` | °C | Безопасная температура; выше растёт брак |
| `frTempK`, `frClockK` | коэффициенты | Вклад температуры и частоты (с учётом сложности архитектуры) в процент брака |
| `boardBase` | деньги | Плата без шины, на карту |
| `boardCostPerBit` | деньги | Плата за каждый бит шины |
| `nodeProjectShare` | доля | Какая доля стоимости проекта техпроцесса входит в стоимость разработки карты |
| `maxParallelProjects` | проекты | Сколько проектов можно вести одновременно |
| `nameMaxLength` | знаки | Наибольшая длина имени карты |

**`production`** — производство и склад

| Поле | Единицы | Смысл |
|---|---|---|
| `autoDemandFactor` | множитель | Запас сверх спроса в режиме «Авто» |
| `autoMaxShare` | доля линий | Наибольшая доля линий фабрики для одной карты в режиме «Авто» |
| `storageCostPerUnitMonth` | деньги в месяц за карту | Хранение запаса |
| `liquidationShare` | доля цены | Сколько платят за остаток запаса при снятии карты с производства |
| `fablessYieldProgress` | доля, 0-1 | Где между наименьшим и наибольшим выходом годных техпроцесса работает литейщик для fabless |

**`popularity`** — популярность карт

| Поле | Единицы | Смысл |
|---|---|---|
| `start` | доля | Стартовая популярность новой карты в сегменте |
| `floor`, `cap` | доля | Нижняя и верхняя границы популярности |
| `gainBase` | доля | Прирост популярности от продаж |
| `baselineGain` | доля в день | Фоновый прирост |
| `eraYears` | 2 года | Границы эр популярности (по умолчанию 1990 и 2010) |
| `eraGain`, `eraBaseline` | 3 множителя | Множители прироста и фонового прироста в трёх эрах |
| `oldDecay` | доля в день | Падение популярности устаревшей карты |
| `oldYears`, `oldYearsBefore1990` | годы | Через сколько лет карта считается устаревшей (до 1990 года срок другой) |
| `brandCarry` | доля | Какая доля популярности лучшей карты владельца переходит новой |

**`background`** — безымянные карты рынка

| Поле | Единицы | Смысл |
|---|---|---|
| `enabled` | да/нет | Есть ли фон |
| `techLagYears` | годы | Отставание технологий фона |
| `popularity` | доля | Популярность фоновых карт |
| `refreshMonths` | месяцы | Как часто фон обновляется |
| `priceFactor` | множитель | Цена фона как доля бюджета сегмента |

**`rivals`** — выпуск соперников

| Поле | Единицы | Смысл |
|---|---|---|
| `maxProductsPerSegment` | карты | Сколько карт одного производителя продаётся в сегменте |
| `intervalJitterMonths` | месяцы | Случайная добавка к `designIntervalMonths` |
| `priceFloorMarkup` | множитель | Цена не ниже себестоимости с этой наценкой |
| `targetTempC` | °C | Температура, под которую соперник выбирает охлаждение |
| `clockShare` | доля | Какую долю наибольшей частоты берёт соперник |
| `dieJitter` | доля | Случайный разброс площади кристалла |

**`synergy`** — процессоры и видеокарты

| Поле | Единицы | Смысл |
|---|---|---|
| `cpuMax`, `cpuK` | доля, коэффициент | Наибольшая прибавка к рейтингу процессоров от доли на рынке видеокарт и крутизна роста |
| `gpuMax`, `gpuK` | доля, коэффициент | То же для рейтинга видеокарт от доли на рынке процессоров |
| `shareWindowDays` | дни | За сколько дней считается доля |
| `gpuLearningShare` | доля | Какая часть линий карт идёт в освоение техпроцесса процессоров |
| `coDevYears` | годы | Насколько свеж должен быть процессор на том же техпроцессе |
| `coDevFactor` | множитель | Во сколько раз дешевле разработка при совместной разработке |

**`news`**

| Поле | Единицы | Смысл |
|---|---|---|
| `leaderCooldownMonths` | месяцы | Не чаще одного письма о новом лидере на сегмент за это время |

**`console`** — консольные заказы

| Поле | Единицы | Смысл |
|---|---|---|
| `unitsShare` | доля | Карт в день в заказе как доля покупателей сегмента в день: `floor(unitsShare × N)` |
| `minPerfShare` | доля | Предложение принять можно картой не медленнее этой доли производительности лучшей карты сегмента |
| `priceFactor` | доля бюджета | Цена карты в заказе от бюджета сегмента |
| `priceFloorMarkup` | множитель | Цена не ниже себестоимости с этой наценкой: цена `max(priceFloorMarkup × себестоимость, priceFactor × бюджет)` |
| `segment`, `fallbackSegment` | `id` сегментов | Сегмент, по которому меряют предложение, и запасной сегмент, если первый не открыт |
| `offerTimeoutDays` | дни | Сколько дней даётся на ответ |
| `revalidateDays` | дни | Как часто пересчитывается кнопка «Принять» |
| `graceDays` | дни | Окно подсчёта недопоставки, и ранее скольких дней после начала заказ не расторгают |
| `failCancelShare` | доля | Заказ расторгается, если недопоставлено больше этой доли объёма |
| `reputationPenalty` | очки репутации | На сколько падает репутация при срыве заказа |

**`limits`** — размеры списков в сейве

| Поле | Единицы | Смысл |
|---|---|---|
| `products` | карты | Не больше стольких карт в сейве |
| `vendors` | записи | Не больше стольких производителей |
| `ledgerMonths` | месяцы | Сколько месяцев бухгалтерии хранит карта |
| `consoleOrders` | заказы | Не больше стольких консольных заказов |

## Что проверяет загрузка

- Уникальность `id` внутри файла, обязательные поля, имена полей (опечатка в имени поля даёт предупреждение), диапазоны чисел.
- Ссылки: `unlocks` указывает на запись нужной ветки, `requiresNodes` на существующие узлы без циклов, `mergeInto` на существующего производителя, `segments` производителей на сегменты текущего режима.
- `sizeByDecade` и `budgetByDecade` — ровно 7 чисел. Годы от 1971 до 2040. `bindTo` — пустая строка или `ai:<число>`.
- Если не осталось ни одной архитектуры, памяти, охлаждения или сегмента, фича выключается и один раз показывает уведомление с причиной. Файлы нужно починить.

## Примеры

Каждый пример ниже лежит в файле с указанным именем в `<папка игры>/PTMod/content/gpu-product-line/` (или в `l10n`).

### Бюджет сегмента

Запись `consumer` с бюджетом 999 в любом десятилетии. Это сегмент режима `single`, поэтому нужен ещё файл `balance.json`, который этот режим включает. Запись полная: поля не сливаются.

`segments.json`

```json segments-consumer-example
{
  "schema": 1,
  "records": [
    {
      "id": "consumer", "mode": "single", "nameKey": "gpu.seg.consumer",
      "opensYear": 1981, "closesYear": 0,
      "baseSize": 3000000,
      "sizeByDecade": [0, 0.5, 4, 8, 10, 9, 9],
      "budgetByDecade": [999, 999, 999, 999, 999, 999, 999],
      "consumptionTarget": 99, "wPerf": 100, "wUnder": 3.0, "wOver": 1.0, "wObs": 3.0, "wCons": 0,
      "featureReqs": [], "missingFeatureFactor": 0.35,
      "vramReq": [
        { "year": 1981, "v": 0.0625 }, { "year": 1990, "v": 0.5 }, { "year": 1996, "v": 2 }, { "year": 2000, "v": 32 },
        { "year": 2005, "v": 256 }, { "year": 2010, "v": 1024 }, { "year": 2015, "v": 4096 }, { "year": 2020, "v": 8192 },
        { "year": 2025, "v": 12288 }
      ],
      "rivalDieShare": 0.5, "rivalBusTier": 1, "rivalVramFactor": 1.0
    }
  ]
}
```

`balance.json`

```json balance-single-example
{ "schema": 1, "marketMode": "single" }
```

Окно «Рынок» покажет бюджет 999. Чтобы изменить сегмент режима `eras` (например `gaming.mid`), скопируйте его запись из встроенного файла `segments.json` и поправьте нужное поле, не меняя `mode`.

### Несколько чисел баланса

`balance.json` сливается по полям: перечислены только два числа, остальные встроенные.

```json balance-example
{ "schema": 1, "founding": { "cost": 5000000 }, "console": { "unitsShare": 0.1 } }
```

### Новая система охлаждения

Охлаждение появляется в игре в два шага: запись в `coolers.json` и узел `research.json`, который её открывает. Название берётся из ключа текста.

`coolers.json`

```json coolers-example
{
  "schema": 1,
  "records": [
    { "id": "cool.liquid", "nameKey": "gpu.cool.liquid", "year": 2010, "thermalResistance": 0.15, "cost": 35 }
  ]
}
```

`research.json`

```json research-example
{
  "schema": 1,
  "records": [
    { "id": "cool.liquid", "branch": "cooling", "unlocks": "cool.liquid", "year": 2010, "baseDays": 150,
      "monthlyCost": 20000000, "requiresNodes": ["cool.dual"], "requiresGameTechs": [] }
  ]
}
```

`l10n/ru/gpu-product-line.json`

```json l10n-ru-example
{ "gpu.cool.liquid": "Жидкостное охлаждение", "gpu.console.client.sega": "Sega" }
```

`l10n/en/gpu-product-line.json`

```json l10n-en-example
{ "gpu.cool.liquid": "Liquid cooling", "gpu.console.client.sega": "Sega" }
```

### Новое консольное предложение

Новый производитель консоли: запись в `consoles.json` и ключи текста для его названия.

`consoles.json`

```json consoles-example
{
  "schema": 1,
  "records": [
    { "id": "sega.1", "clientKey": "gpu.console.client.sega", "offerYear": 2002, "termYears": 4 }
  ]
}
```

Название производителя консоли — ключ `gpu.console.client.sega`. Он уже есть в файлах текстов `l10n` из предыдущего примера: оба ключа лежат вместе.

### Новый производитель

`vendors.json`. Виртуальный производитель без привязки к компании игры; рынок возьмёт его карты в указанные сегменты.

```json vendors-example
{
  "schema": 1,
  "records": [
    { "id": "voxel", "name": { "ru": "Voxel", "en": "Voxel" }, "series": "Cube", "bindTo": "",
      "entryYear": 1999, "exitYear": 2008, "mergeInto": "", "mergeYear": 0,
      "techLag": 1.0, "priceFactor": 0.9, "capacityShare": 0.2, "designIntervalMonths": 18, "strength": 0.5,
      "segments": ["gaming.high", "gaming.mid"], "color": "#8E24AA" }
  ]
}
```

## Если что-то не работает

- Откройте `Player.log` (см. главный README) и найдите строки `[gpu-product-line]`. Там названы файл, запись и поле, которое не прошло проверку.
- Запись не заменила встроенную: проверьте `id` (совпадает ли до буквы) и что у файла `schema` равна `1`.
- Сегмент не виден: проверьте `mode` записи и `marketMode` в `balance.json`.
- Часть не появилась в конструкторе: у неё должен быть узел в `research.json` с `unlocks`, а сам узел нужно изучить.
- Вместо названия показан `id`: нет текста с таким ключом в `l10n`.
- Фича выключилась сама после правки: в логе причина (`the feature is switched off`); верните встроенный файл и править по одной записи.
